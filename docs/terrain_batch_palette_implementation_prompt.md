# 実装窓向けプロンプト: 地形バッチと基準パレット再コンパイル

以下を実装してください。正本仕様は `docs/spec/terrain_batch_palette_spec.md` です。

## 目的

SRPG用64×64地形原画をGUIでまとめて変換し、各結果の使用色を確認して、一枚のパレットへ選択画像を統一再コンパイルできるようにする。
「画像を追加 → まとめて変換 → 使用色を比較 → 一枚を基準に選択 → 対象をチェック → 原画から再変換 → 前後比較」まで接続する。

## 最初に確認

1. AGENTS.mdと適用スキルを読み、現在の差分を確認する。他作業の変更を保全する。
2. 仕様書と `src/pixel_tile_compiler/gui/main_window.py`、`src/pixel_tile_compiler/gui/input.py`、`src/pixel_tile_compiler/gui/policy.py`、`src/pixel_tile_compiler/pipeline/compiler.py`、`src/pixel_tile_compiler/pixelizer/palette.py`、関連テストを読む。
3. `e2e/map_tiles_20260907_source_preserving_batch/batch_manifest.json` の現在の形式・参照画像を確認する。過去のテスト件数を現在の検証結果として流用しない。

## 必須契約

- 地形に限定。日本語UIと単画像・キャラクター変換の既存動作を維持する。
- 個別変換の既定は元絵を保持（nearest）、24色、repeat無効。
- パレットの正本は選択したfinalの実使用RGB。debug色見本を読み戻して基準にしない。metadataを使う場合はfinalと照合する。
- 実使用22色なら基準も22色。予算24色に合わせて補充しない。結果は基準集合の部分集合でよい。
- 固定色は既存`CompilerConfig.palette_colors`を再利用する。完全透明と上限超過は基準選択不可。
- 再変換は原画から。前回結果の完全な条件を引き継ぎ、固定パレット指定だけを変更する。
- 原画hash不一致・欠落・復元不能な条件は明示する。推測で埋めず、その行の再変換を止める。
- 実行開始時に対象・基準色・原画情報・条件・前回結果IDを凍結する。基準自身の再変換でも参照色を更新しない。
- 新runへ保存し、既存原画・出力・試作manifestを上書きしない。同名原画も衝突させない。
- GUIをブロックしない単一ワーカーで逐次処理する。一件失敗は続行、中止は現在の一件の終了後に反映する。
- 一覧の行選択と対象チェックを分離する。前後比較は同倍率の最近傍表示。
- 旧試作manifestを読み込めること。原画欠落でもfinalの閲覧と基準色抽出は可能にする。

## 実装の進め方

仕様書のP0→P1→P2の順に、受け入れ条件の失敗テスト→最小実装→責務整理を進める。
MainWindowへデータ管理・保存・実行・読込処理を集約せず、Qt非依存のモデル／サービスと画面を分ける。
新規依存は追加しない。手動パレット編集、色の自動補正、役割別パレット、キャラクターバッチは実装しない。
保存契約・パレットID・エラー処理・操作可否は仕様書に従う。

## 検証と成果物

1. 固定色の部分集合、透明RGB除外、原画からの再変換、スナップショット不変、衝突・上書き防止、失敗継続と中止、旧manifest読込をテストする。
2. 現在の10枚を使い、一枚を基準に統一前後の比較画像とmanifestを新規検証ディレクトリへ保存する。基準のファイル名・hash・実使用色を報告する。
3. 色集合の機械判定と見た目の評価を分ける。共通色でも陰影・描き込み・接続形状は揃わないことを比較の限界として記録する。
4. focused regression、既存全体テスト、compileall、diff check、編集した日本語ファイルのU+FFFD検査を行う。
5. GUIは可能ならネイティブ操作で確認する。offscreenのみなら、その範囲と未実施の手動QAを明記する。
6. `docs/terrain_batch_palette_handoff.md` に変更内容、実行方法、検証結果、比較成果物、制約、残作業を残す。

コミット・pushは行わず、変更と成果物をレビューできる状態で報告してください。
