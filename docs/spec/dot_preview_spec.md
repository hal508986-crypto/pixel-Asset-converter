# ドット確認画像の書き出し

## 0. 実装担当への前提

本書は設計書であり、記載する追加機能は未実装。
コンパイル結果を加工した**別ファイル**を作るだけで、`final.png` そのものは変更しない。

- G-1: 3節のスコープ表の範囲内で実装する。コンパイル結果の画素は書き換えない。
- G-2: 受け入れ条件に対応する失敗テストを先に作り、最小実装後に責務分離を確認する。
- G-3/G-4: 新規依存はゼロ。Pillow・標準ライブラリのみ。
- G-5: 範囲・判定規則の変更は本書を更新してから実装する。
- `fable-judgment`、`tdd-first`、GUI変更は `ui-design-system` に従う。
- GUI文言は既存画面の語彙に合わせる（ドット / 格子 / 出力）。

## 1. 目的

出力が本当にドット単位で揃っているかを目視で確かめられるようにする。あわせて、
ドット感を強調した見せ物用の画像も作れるようにする。

## 2. 前提

出力は等倍で1画素＝1ドットのため、**そのままでは格子線を引く隙間がない**。
格子を見せるには整数倍へ拡大する必要がある。GUIのドットプレビューが倍率4以上でのみ
格子を描いているのも同じ理由（[main_window.py](../../src/pixel_tile_compiler/gui/main_window.py) `drawForeground`）。

保存される既存の成果物に格子入りのものはない。アニメーションの `preview_8x.png` は拡大のみ。

## 3. スコープ表

### やる

| ID | 内容 |
|---|---|
| S-1 | コンパイル結果を整数倍へ拡大し、1ドット境界に格子線を引いた**検査用**画像を作る |
| S-2 | ドットごとの区切りを付けた**見せ物用**画像を作る |
| S-3 | GUIから明示的に書き出す導線を用意する |

### やらない

| ID | 内容 | 理由 |
|---|---|---|
| N-1 | コンパイルのたびに自動生成する | アニメーションではコマ数分増えて出力が重くなる。明示操作にする |
| N-2 | `final.png` の画素を変更する | 確認画像は別ファイル。正本を汚さない |
| N-3 | 格子の色・太さ・間隔をGUIから設定させる | まず既定で運用する。必要になってから開ける |
| N-4 | アニメーションの全コマ書き出し | まず1枚（現在プレビュー中のコマ）から。必要なら後で広げる |
| N-5 | 非整数倍の拡大 | ドット境界がぼやけて検査にならない |

### いつか

| ID | 内容 |
|---|---|
| L-1 | アニメーション全コマの一括書き出し（N-4の解除） |
| L-2 | 格子の見た目の設定（N-3の解除） |

## 4. 設計

### 4.1 倍率の決め方

長辺が768px前後に収まる整数倍を選ぶ。格子が見える下限として4倍、上限は16倍。

```
scale = clamp(768 // max(width, height), 4, 16)
```

64×64なら12倍（768px）、128×128なら6倍（768px）、256×256なら4倍（1024px）、
512×512なら4倍（2048px）。**上限で頭打ちにするため、大きいCanvasでは長辺が768を超える。**
検査には支障がないので許容する。

#### 大きいCanvasでのメモリ

出力Canvasの上限が1280へ上がったため（[Canvas拡張仕様](canvas_scale_and_palette_budget_spec.md) 4.10節）、
1280×1280は倍率4で5120×5120になる。ここで画像全体を `float64` へ通すと
1画素あたり32バイト要り、**それだけで800MB超**になる（実測ピーク1.8GB）。

倍率の契約は変えず、**計算方法だけ**を変える。

- 線の合成と縁の暗転を、256要素の**対応表**（uint8→uint8）で行う。線色・アルファ・暗転率は
  固定なので、画素ごとに掛け算をやり直す必要がない。
- 対応表の適用は行の帯（512行）に切り、一時配列をCanvasサイズによらず一定に保つ。
- 市松模様の生成で `np.where` が `int64` の中間配列を作るのをやめ、面ごとに塗り分ける。

**交点は2段ぶんを1枚の表に畳む。** 濃い線の間隔は細い線の整数倍なので、濃い線の位置は
必ず細い線の位置でもある。書き換え前はfloatのまま2回重ねてから最後に切り捨てていたため、
表を2枚に分けて順に当てると交点だけ1階調ずれる（実素材で確認済み）。
細い線だけの表と、細い線の上に濃い線を重ねた表の2枚を用意し、交点には後者だけを当てる。

対応表は書き換え前と同じ式（`floor(v*(1-a) + c*a)` / `floor(v*ratio)`）で作るため
**出力は1画素も変わらない**。実測は1280×1280で 1.8GB/7.0秒 → 500MB/2.5秒。

### 4.2 検査用（`inspect`）

- 元画像を `NEAREST` で整数倍へ拡大する。
- 1ドット境界すべてに1px の格子線を引く。線は半透明の中間色とし、明るい絵でも暗い絵でも見える。
- **8ドットごとに濃い線**を引く。ドット数を数えられるようにするため。
- 透明部分は市松模様の上に合成する。Canvasの範囲とアルファの抜けが同時に見える。

### 4.3 見せ物用（`showcase`）

- 元画像を `NEAREST` で整数倍へ拡大する。
- 各ドットの右辺と下辺に、そのドット色を暗くした1pxの線を入れる。硬い格子ではなく、
  タイルが並んでいるように見せる。
- **透明なドットは透明のまま**にする。区切り線も入れない。

### 4.4 出力先と名前

現在のコンパイル結果と同じディレクトリへ書く。倍率を名前に含めて自己説明的にする。

| 種類 | 名前 |
|---|---|
| 検査用 | `final_grid_{scale}x.png` |
| 見せ物用 | `final_dot_{scale}x.png` |

### 4.5 GUI

「コンパイル結果」タブのプレビュー下にボタンを置く。結果が無いときは無効。

| 場所 | 文言 |
|---|---|
| ボタン | `ドット確認画像を書き出す` |
| ツールチップ | 「コンパイル結果を拡大し、格子付き（検査用）とドット強調（見せ物用）の2枚を出力フォルダへ書き出します」 |
| 完了時の状態表示 | `ドット確認画像を書き出しました: {検査用の名前} / {見せ物用の名前}` |
| 結果が無いとき | ボタンを無効にする |
