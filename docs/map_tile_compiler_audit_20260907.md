# 64px MAPタイルコンパイル調査

調査日: 2026-09-07。対象: `E:\ena-dri\repos\pixelart-compiler` の当日の作業ツリー。
実装依頼は [実装担当向けプロンプト](map_tile_compiler_implementation_prompt.md) を参照。

## 目的と結論

キャラクターの64×64px・128×128pxコンパイルに続き、ピクセルアート風の入力画像を、SRPGで採用できる64×64pxのMAPタイルへコンパイルするための不足を調べた。

64pxへの再構成、減色、素材合成、道・川の論理接続は既にある。主要な不足は、地形の構造と隣接関係を最終PNGまで保持し、タイル一式として採用判定する統合経路である。64pxを16pxなどへ落とすことを解決策としない。

## 確認方法と限界

- 現行ソース、既存テストの内容、README、HANDOFF、ADR-0003を読んだ。
- 反復補正とシート縮小について、Python 3.10で小さな合成画像を直接処理した。
- `e2e/river_network_study/maps/comparison.png` を目視した。保存済み成果物であり、現行コードで再生成した画像ではない。
- 全テスト、実画像の再コンパイル、SRPG側の最新取り込み仕様・実機表示は未検証。
- Python 3.11では今回の直接検証時にnumpyが見つからず、3.10で実行できた。実装担当は環境を再確認すること。
- コード変更は行っていない。調査時点で `gui/main_window.py`、`gui/policy.py`、`tests/test_gui.py` に既存変更があり、未追跡成果物も存在した。

## 主要な不足

### P0-1: 自己反復補正と隣接契約の衝突

観測した事実:

- `CompilerConfig` は反復最適化が既定で有効。
- `transition_network/network.py`、`river.py`、`transition.py` のピクセル化は `tile_mode="repeatable"` を指定する。
- `tileset/compiler.py` とMAPコンパイルの既定経路も同様の処理の影響を受ける。
- `tile/repeatability.py` は画像自身の左右端・上下端を対応させる。隣接タイルの契約や地形マスクは受け取らない。

再現: 64×64 RGBA画像の上半分を `(30,140,40,255)`、下半分を `(150,90,40,255)` とし、`optimize_repeatability(image, center_suppression_strength=0)` を実行。192ピクセルが変更され、異なっていた北端・南端が同一になった。

推論: 北が草・南が土の境界や曲がり道に対し、自己反復補正は構造を壊し得る。これは関数単体の再現であり、全実画像やパイプライン全体の破損率を測った結果ではない。

必要な対応: 自己反復、契約付き隣接、MAP固定配置を区別する。減色・クラスタ整理を含む最終段まで端点、幅、境界を保護する。反復補正を止めるだけで全問題が解決したと扱わない。

### P0-2: 生成シート取り込みとコンパイルの未接続

`asset/pipeline.py::process_generated_sheet()` は分割画像を直接保存し、`PixelTileCompiler` を呼ばない。`sheet/normalizer.py::normalize_tile()` の `pixel_preserving` はNEAREST縮小と同じ。

再現: 128×128の不透明画像を `R=x, G=y, B=70` で作り、64×64へ `pixel_preserving` で縮小すると4,096色が残った。色数の多さ自体を不合格とする証拠ではなく、この処理が減色を行わないことの確認である。

必要な対応: 元シートのセル領域から、共有スタイル・パレットを用いる64pxコンパイルへ接続する。先に64pxへ縮小してから高解像度の領域解析を行う順序にしない。既存の分割のみの経路は互換性を保つ。

余白・ガター・セル位置の揺れがある生成画像を、等分割だけで正しく解釈できるとは仮定しない。初期対応は明示的な切り出し指定または入力拒否でよく、万能な自動検出は別課題。

### P0-3: 最終PNGの構造検証と採用ゲート不足

- `tileset/evaluator.py::validate_contract_adjacency()` は接続IDの一致を確認する。
- `validate_edge_profiles()` は画素側のリスクを集計するが、未比較の辺ではscore=0となる。未検証を合格と混同しない。
- `tileset/compiler.py` は画素側リスクを記録するが、不一致を採用不可として止める経路にはなっていない。
- `transition_network/metrics.py` の道路連続性指標の一部は渡されたマスクを測る。完成PNGの構造保持の証明とは別。
- `asset/pipeline.py::validate_asset_package()` は主にmanifest、ファイル存在、寸法を確認する。

必要な対応: 完成PNGについて、許可された隣接辺、四隅、接続の幅・位置、非接続辺への漏れ、色数・アルファを検証する。入力マスクの整合性と画像の整合性は分けて報告する。色による意味推定には限界があるため、保護マスク等を処理に伴走させても、完成PNGとの対応を別途確認する。

契約違反の失敗例を実際に拒否すること。平均スコアで局所破損を隠さず、未検証状態を保持する。美観のスコアだけで自動採用しない。

## 次段階の不足

| 項目 | 不足と方針 |
|---|---|
| 境界形状 | `TransitionTileCompiler.build_pair()` はNS/EW。内角・外角・孤立部分などを固定地形配置から解決する仕組みが必要 |
| 地形の画風 | 既存研究を通常経路へ接続し、素材ごとの塊・密度・陰影を揃える。キャラクターのbboxフィットや余白を地形へ適用しない |
| 構造入力 | TileIRには領域やMAP周辺情報があるが、地形の保護マスク・最終辺契約を全処理へ伝える統合が不足 |
| GUI | `gui/main_window.py` は単体 `PixelTileCompiler` を呼ぶ。タイル群の取り込み、隣接確認、部分差し替えまでの導線は別途必要 |
| ゲーム連携 | 汎用manifestはある。ゲームの実在する地形IDとの対応、再取り込み、実寸表示までのE2Eは未確認。移動コスト等を推測で生成しない |

既存の川MAP比較画像では、川周辺の短い横筋と森林の細かな反復模様が見られた。原因の断定や現行実装の品質判定には使わず、再比較の観点として扱う。

## 対象経路の区別

今回の主対象は自由に配置して再利用するタイルセット。

`docs/adr/0003-map-visual-bake.md` の一枚絵MAP→64px chunksは別経路。MAP専用断片を汎用地形タイルへ自動昇格しない。論理MAPは正本であり、画像都合で書き換えない。

## 推奨実装順と完了条件

1. 既存経路を再確認し、自己反復と隣接契約の衝突を回帰テストで再現する。
2. 草・土・草土境界・道の小セットで最終64pxの接続を保護する。
3. シート取り込み→共有条件でのコンパイル→パッケージを一本通す。
4. 完成PNGの拒否ゲートと、固定MAP・実寸・整数拡大の比較を作る。
5. 内外角を含む地形配置へ拡張し、ゲーム側契約確認後に取り込みを検証する。

初回の完了は1〜4を中心とする。5の境界拡張、GUI、実ゲーム連携は後続として明示し、途中の状態を「ゲーム採用まで完了」と報告しない。

受け入れ条件: 全タイル64×64、欠落・重複なし、宣言した色数とアルファ条件、同一入力・設定・seedの再現性、最終接続保持、違反時の拒否、元画像不変、既存キャラクター64px/128pxと単体反復の回帰確認。美観は実画像で人が確認する。
