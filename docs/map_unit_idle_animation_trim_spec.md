# MAP駒待機アニメーション向け自動トリミング・共通配置仕様

作成日：2026-09-07。

## 目的

SRPG用MAP駒の待機アニメーションを、生成原画から実機用64×64pxフレームへ安定して変換する。

対象は、同一キャラクターの4フレーム程度の微小な待機モーションを主用途とする。各フレームを個別に自動トリミング・中央配置すると、髪やリボンの揺れ、bbox差、半透明ノイズによって人物全体が1px単位でぶれるため、アニメーション単位で共通スケールと共通アンカーを使う。

本仕様は、既存のキャラクター向け変換で採用している「背景・アルファ解決 → 可視範囲抽出 → 縦横比維持の最近傍縮小 → 減色 → 出力座標で配置」という責務分離を維持し、連番・スプライトシートへ拡張する。

## 基本方針

自動トリミングは「フレームごとに余白を最小化する機能」ではなく、「全フレームを同一基準で安定配置するための測定処理」として扱う。

禁止する基本動作：

- 各フレームを独立にtrimしてから個別に中央配置する。
- 各フレームごとに異なる縮小率を決める。
- 髪先やリボンの1px差によってキャラクター全体の中心や足元位置を動かす。
- 完全透明に近い孤立ノイズをbboxへ無条件に含める。

推奨する基本動作：

- 各フレームの可視bboxは個別に計測する。
- 配置・縮小に使うbboxはアニメーション全体から共通基準を作る。
- 全フレームで同一縮小率を使う。
- 水平中央と足元アンカーを全フレームで固定する。
- bbox、スケール、アンカー、最終配置を検証情報として出力する。

## 想定入力

### 単一フレーム

既存の正面MAP駒原画。背景処理後に1体の人物が残る画像。

### 横一列の待機アニメーションシート

同一キャラクターの複数フレームを左から右へ並べた生成原画。

初期想定：

- フレーム数：4
- 順序：F1, F2, F3, F4
- 最終実機サイズ：各64×64px
- 最終スプライトシート：256×64px

生成原画そのものが256×64pxである必要はない。高解像度原画では、4分割後の各領域を独立したソースフレームとして扱う。

入力シートの分割方法は、初期実装では「横幅をフレーム数で等分」を基本とする。幅がフレーム数で割り切れない入力、人物がセル境界を越える入力、余白が極端に不均一な入力は検証エラーまたは明示的なoverride対象とする。

## 処理順

1. 入力読込
2. シートの場合はフレーム分割
3. 各フレームの背景・アルファ解決
4. アルファ閾値による可視mask生成
5. 必要なら微小な孤立成分を除去
6. 各フレームの可視bbox計測
7. アニメーション全体の共通bbox・共通スケール決定
8. 各フレームを同一倍率で最近傍縮小
9. 可視画素のみを対象に減色
10. 必要な場合だけ輪郭処理
11. 共通アンカーで64×64キャンバスへ配置
12. 4フレームを256×64へ再結合
13. PNGと検証情報を出力

背景除去、縮小、減色、配置の責務を混在させない。

## 可視mask

### アルファ閾値

完全透明か否かだけでbboxを取ると、生成画像由来の半透明ゴミを拾う場合がある。

初期候補：

```text
alpha_threshold = 16
visible = alpha >= alpha_threshold
```

閾値は設定可能とする。既に二値アルファ化された入力では実質的な挙動差を生じないこと。

### 微小孤立成分

外周や人物から離れた1〜2px程度の孤立成分がbboxを広げないよう、connected componentによる除去を任意で有効化できるようにする。

初期候補：

```text
remove_isolated_components = true
min_component_area_px = 3
```

ただし、キャラクター本体から実際に離れている小さな装飾、武器先端、髪飾りなどを削除し得るため、既定値は実画像で確認して決定する。完全自動で常に安全とは扱わない。

## bbox計測

各フレームについて次を記録する。

```text
left
 top
right
bottom
width
height
visible_pixel_count
```

完全透明フレームは正常な待機フレームとして扱わず、エラーまたは警告にする。

### union bbox

初期推奨方式は、全フレームのbboxの和集合を共通基準にする。

```text
union_left   = min(frame.left)
union_top    = min(frame.top)
union_right  = max(frame.right)
union_bottom = max(frame.bottom)
```

これにより、F4だけリボンが1px外へ揺れる場合でも、F4だけ別倍率で縮小されたり、人物中心が移動したりすることを避ける。

必要ならunion bboxへ一定のpaddingを追加する。

初期候補：

```text
padding_px = 1
```

paddingは入力側ではなく、共通bbox計算の責務として明示する。

## 共通スケール

全フレームで同一縮小率を使用する。

初期候補の描画枠：

```text
fit_width  = 54
fit_height = 54
```

共通bboxがこの枠へ収まる最大倍率を1回だけ計算し、その倍率を全フレームへ適用する。

```text
scale = min(fit_width / union_width, fit_height / union_height)
```

実装上の整数丸めと最近傍縮小による1px差はテストで固定する。

禁止：

```text
scale_F1 != scale_F2
scale_F2 != scale_F3
```

個別bboxフィットによる見かけ上の膨張・収縮を発生させない。

## 共通アンカー

### 水平

初期既定：

```text
anchor_x = center
```

64×64キャンバスの水平中心へ人物の共通基準を揃える。

髪やケープの非対称な揺れによってbbox中心がフレームごとに変化しても、配置基準を個別再計算しない。

### 垂直

初期既定：

```text
anchor_y = foot
```

靴底の接地ラインを固定する。待機アニメーションでは足元を動かさず、膝・胴・肩・髪などの変化によって呼吸や重心移動を表現することを前提とする。

初期候補：

```text
bottom_margin_px = 6
```

既存アリア素材で得られた下余白7pxは比較材料であり、全キャラクター共通の契約にはしない。既定値は実画像比較で決定する。

## 足元アンカーの決定

初期実装では、可視bboxのbottomを足元候補として扱える。ただし、マント・杖・武器・エフェクトなどが足より下へ伸びるキャラクターでは破綻する。

そのためAPI・設定は将来の拡張を妨げないものとし、少なくとも次のoverrideを許容する。

```text
anchor_offset_x
anchor_offset_y
foot_y_override
bbox_override
scale_override
```

初期対象の「正面・武器なし・2頭身MAP駒」では自動推定を優先する。

## フレーム間整合性

待機アニメーションの主目的は「同一キャラクターの微小な動き」であり、次を機械的または人手で確認する。

- 出力キャンバスは全フレーム同じ64×64。
- 縮小率は全フレーム同一。
- 足元アンカー位置が一致する。
- 水平中心が一致する。
- 透明色と可視色数の計測方法が一致する。
- フレームごとに見切れが発生していない。
- F1とF3などの類似フレームで、顔や胴が不必要に1px横移動していない。

AI生成由来の「前髪、顔、袖、リボン、ケープの形そのものが描き直されている」問題は、トリミングだけでは解決できない。コンパイラは決定論的な配置揺れを増やさないことを責務とし、生成時の造形差まで自動修正するとは扱わない。

## 設定例

```json
{
  "animation": {
    "enabled": true,
    "layout": "horizontal",
    "frame_count": 4,
    "frame_order": ["F1", "F2", "F3", "F4"]
  },
  "trim": {
    "enabled": true,
    "alpha_threshold": 16,
    "remove_isolated_components": true,
    "min_component_area_px": 3,
    "padding_px": 1,
    "bbox_mode": "measure_each_frame_apply_union"
  },
  "scale": {
    "mode": "uniform_across_all_frames",
    "fit_within_px": {
      "width": 54,
      "height": 54
    },
    "resample": "nearest"
  },
  "placement": {
    "canvas_size_px": {
      "width": 64,
      "height": 64
    },
    "anchor_x": "center",
    "anchor_y": "foot",
    "bottom_margin_px": 6
  },
  "output": {
    "frame_size_px": {
      "width": 64,
      "height": 64
    },
    "sheet_layout": "horizontal",
    "sheet_size_px": {
      "width": 256,
      "height": 64
    }
  },
  "validation": {
    "check_same_scale": true,
    "check_same_anchor": true,
    "check_binary_alpha": true,
    "check_no_clipping": true,
    "export_bbox_report": true
  }
}
```

このJSONは契約案であり、既存の`CompilerConfig`へそのまま追加することを要求しない。既存の責務分離、CLI/GUI、将来の任意サイズ対応を確認したうえでデータモデルへ落とす。

## 検証レポート

少なくともフレームごとに次を出力可能にする。

```text
frame_id
source_size
visible_bbox
union_bbox
visible_pixel_count
scale
placed_bbox
anchor_x
anchor_y
clipped
visible_color_count
alpha_values
```

アニメーション全体について次も出力する。

```text
frame_count
common_scale
common_anchor
output_frame_size
output_sheet_size
max_bbox_delta
```

人間確認用に、実寸64×64フレームと最近傍8倍プレビューを生成できることが望ましい。

## 受け入れ条件

- 4フレームを処理した際、全フレームの縮小率が一致する。
- 4フレームを処理した際、足元位置と水平中心が一致する。
- F4だけ髪やリボンが1px広がっても、F4だけ人物全体が縮小されない。
- 透明または半透明の孤立ノイズがbboxを不必要に広げない。
- 人物の一部がunion bbox内に存在する限り、縮小・配置で見切れを発生させない。
- 単一フレームの既存キャラクター変換を壊さない。
- 地形向け変換経路を壊さない。
- 64×64の各フレームと256×64の横一列シートを機械的に検証できる。
- 同じ入力・同じ設定では同じ配置結果を返す。

## 実装優先順位

### Phase 1

- フレーム分割
- alpha mask
- 各フレームbbox計測
- union bbox
- 共通スケール
- center-x + foot-y配置
- 64×64フレームと横一列シート出力
- 基本検証

### Phase 2

- 微小孤立成分除去
- padding設定
- bbox/anchorレポート
- 8倍プレビュー

### Phase 3

- 手動anchor/bbox/scale override
- 武器・マント・騎乗などを考慮した足元推定
- フレーム間の位置差・形状差メトリクス
- 4フレーム以外の任意枚数対応の強化

## 非目標

初期実装では次を行わない。

- AIが各フレームで描き直した顔・髪・衣装を同一画素へ補正する。
- オプティカルフローで中割りを生成する。
- フレーム補間を行う。
- 生成モデルの画像を手打ちドット絵と同等とみなす。
- 全キャラクター種別に対して完全自動の足元推定を保証する。
- 静止画と連番で別々の背景除去アルゴリズムを再実装する。
