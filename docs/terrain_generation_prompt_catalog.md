# 草原・草原の道・川：画像生成プロンプトと実験条件

作成: 2026-09-07。目的は実ゲームで駒が読みやすい64px地形の探索。以下は生成指示であり、生成器が寸法・接続・色を厳密に守る保証ではない。採用前に実画像とコンパイル結果を検査する。

## 使い方

今のGUIには、1画像＝64×64の1タイルとして入力する。4×4シートを入力すると画像全体が1タイルに縮む。シート分割コンパイルはCLIの別経路。

最初の比較設定は「地形／元絵を保持／24色／繰り返し最適化なし」。道・川は自己反復と指定隣接が異なるため、繰り返し最適化を有効にしない。GUIの単体出力だけでネットワークの接続検証が済んだと扱わない。

下の単体プロンプトをそのまま使い、必要に応じて接続指定・彩度指定だけを差し替える。選んだ草原画像を道・川の背景参照として添付するときは、地面の色・草の大きさ・光源を合わせるための参照だと明記する。

## A. 草原：単体プロンプト

```text
SRPG用の草原タイルのコンパイル原画を1枚生成してください。
正方形1024×1024。画像全体で1マスを表し、タイルシートにはしない。
真上から見た地面のみ。画像の端まで不透明な草地を描き、余白なし。

最終的に64×64pxへ変換しても読めるピクセルアート風。
草の葉先の明部、葉のまとまり、根元の暗部を意図的な色の塊で描く。
細かな点描や一本ずつの葉の描き込みより、形の読みやすさを優先する。
落ち着いた地面を広く残し、小さな草のまとまりをまばらに散らす。
中央に大きな草の塊を置かず、配置密度と明るさを全体で均一にする。

色は彩度を控えた緑・オリーブ系。灰色一色にはせず、葉の明暗は残す。
黄色いハイライトは控えめにし、蛍光色や鮮烈な黄緑を使わない。
光は柔らかく左上から。強い影、白い反射、画面全体の明暗勾配は付けない。
ゲームの駒を重ねたときに、地面が駒より目立たない背景にする。

上下左右に自然につながる草地。縁に装飾や枠を作らない。
人物、花、木、岩、道、川、建物、空、地平線、文字、番号、罫線、
額縁、ガター、ぼかし、写真のような質感、細かなディザは禁止。
```

## B. 草原の道：単体プロンプト（南北直線）

```text
SRPG用の「草原を通る土の道」タイルのコンパイル原画を1枚生成してください。
正方形1024×1024。画像全体で1マスを表し、タイルシートにはしない。
真上から見た地面のみ。不透明、余白なし。

最終64×64pxで読みやすいピクセルアート風。
背景は彩度を控えた緑・オリーブ系の草原。
小さな草のまとまりをまばらに配置し、地面の情報量を抑える。
道は彩度を控えた茶・土色。草原と明度・色相を区別するが、
明るい黄色や白い縁取りで目立たせない。
道の中は踏み固めた土の落ち着いた面とし、細かな石や轍を増やさない。
左上からの柔らかい光で統一し、葉先と根元の明暗は残す。

接続指定：北と南だけにつながる直線の道。
道は上辺中央から下辺中央へ切れずに続く。
左右の辺には道を出さない。
接続位置は辺の正確な中央。道幅は辺長の22パーセント。
画像端付近では幅と位置を一定にし、端へ向けて広げたり細めたりしない。
道の外側は草原。道の境界を強い黒線や影で囲まない。

人物、花、木、大きな岩、橋、川、建物、看板、矢印、空、地平線、
文字、番号、罫線、枠、余白、ぼかし、写真のようなノイズは禁止。
```

背景参照を添付するときの追記:

```text
添付画像は草原の画風・色・草の大きさ・光源の参照です。
背景を同じ草原として揃え、指定した道だけを追加してください。
```

22%は現行road契約 `connector_width_ratio=0.22` に合わせた指定。生成で保証される値ではない。現行ゲートは最終64pxで15px幅を期待するため、元画像と縮小後の両方を検査する。美観比較と契約合格は別。

## C. 川：単体プロンプト（南北直線）

```text
SRPG用の「草原を流れる細い川」タイルのコンパイル原画を1枚生成してください。
正方形1024×1024。画像全体で1マスを表し、タイルシートにはしない。
真上から見た地面と水面のみ。不透明、余白なし。

最終64×64pxで読みやすいピクセルアート風。
背景は彩度を控えた緑・オリーブ系の草原。
川の水は落ち着いた青緑・青灰色。草原と明確に区別できる色相にする。
鮮烈なシアン、白い泡、鏡のような反射、透明な写真風の水は使わない。
水面は少数の広い明暗と控えめな短い流れ模様で表現する。
川岸は控えめな土色の細い帯。岩や植物を密集させない。
光は左上からの柔らかい光で統一する。

接続指定：北から入り南へ出る川。
水面は上辺中央から下辺中央へ切れずに続き、左右の辺には出さない。
接続位置は辺の正確な中央。水面幅は辺長の26パーセント。
川岸は水面の外側に片側およそ4パーセントの幅で添える。
画像端では水面幅と川岸幅を一定にし、内部だけに穏やかな曲がりを許す。
滝や段差は作らない。川岸と水面を途中で分断しない。

人物、魚、舟、橋、木、大きな岩、建物、空、地平線、強い水しぶき、
文字、矢印、番号、罫線、枠、余白、ぼかし、細かなノイズは禁止。
```

26%・4%は既存RiverRenderSpecの既定値を参考にした生成比較条件。現在の道路シートプリセットへそのまま渡せるという意味ではない。川用の生成シートプリセットは `generation/presets.py` では未対応。River Rendererと一般のシート経路は区別する。

## 道は16種類で何が揃うか

上下左右の4辺について接続の有無を選ぶと2^4=16通り。一定幅・辺中央接続の道の基本形はこれで揃う。道路がある画像は15種類で、残り1種類は道なしの地面。

以下の順は既存roadプリセットの4×4セル順（左から右、上から下）と一致する。

| 行・列 | 接続 | 単体プロンプトの「接続指定」の差し替え |
|---|---|---|
| 1・1 | EMPTY | 道なし。背景だけ |
| 1・2 | N | 北だけにつながり、中央付近で自然に終わる |
| 1・3 | E | 東だけにつながり、中央付近で自然に終わる |
| 1・4 | S | 南だけにつながり、中央付近で自然に終わる |
| 2・1 | W | 西だけにつながり、中央付近で自然に終わる |
| 2・2 | NS | 北と南をつなぐ直線 |
| 2・3 | EW | 東と西をつなぐ直線 |
| 2・4 | NE | 北と東をつなぐ曲がり角 |
| 3・1 | NW | 北と西をつなぐ曲がり角 |
| 3・2 | SE | 南と東をつなぐ曲がり角 |
| 3・3 | SW | 南と西をつなぐ曲がり角 |
| 3・4 | NES | 北・東・南が中央でつながるT字 |
| 4・1 | NEW | 北・東・西が中央でつながるT字 |
| 4・2 | NSW | 北・南・西が中央でつながるT字 |
| 4・3 | ESW | 東・南・西が中央でつながるT字 |
| 4・4 | NESW | 上下左右が中央でつながる十字路 |

差し替える際は「左右には出さない」等の元の方向指定も置き換える。常に「指定した辺にだけ接続」とする。異なる形を画像回転で作ると光源も回転するため、光源を揃えたいセットでは単純回転で量産しない。

現行ゲートのEMPTYは `uniform_background` の明示規則を使用する。草の模様付きの道なし画像はその規則と一致しない。現行道路パッケージの合格確認用EMPTYは単色背景にし、実ゲームで草模様を使う場合のEMPTY契約は別途検討する。生成プロンプトだけでこの制限を解決したと扱わない。

16種類に含まれないもの: 道幅の変化、斜め辺への接続、橋、階段、崖の上下、異なる地面との遷移、同じ形の見た目違い。必要な場合に追加する。

## 川は16種類で十分か

細い線状の川を4方向へつなぐ見た目だけなら道路に近い分類が使えるが、自然な川・実装の流向制約まで含めて「16枚で過不足なし」とは言えない。

- 現行Riverは十字交差を拒否。T字は基本的に2本が入り1本が出る合流。通常の分流や循環も制限される。
- 流向を絵に描かないなら、直線2＋曲線4＋端点4＋T字4＝14形状（道なし相当を含め15）が形状の整理として使える。ただし端点は水源等として意味を付け、合流はグラフに合わせる。
- 流向を描き分ける場合、同じNSでも北→南と南→北が別。T字も出口がどの辺かで別になり、形状数より画像数が増える。
- 広い川・湖・河口には、水面中心、岸の内外角、幅の変化などの面を構成するタイルが別途必要。

最初の生成比較は下表の6枚で十分。背景・水面幅・岸幅・光源を固定し、川プロンプトの接続指定を置き換える。

| 候補 | 接続・流向 |
|---|---|
| river_NS | 北から南へ |
| river_EW | 西から東へ |
| river_NE | 北から東へ曲がる |
| river_NW | 北から西へ曲がる |
| river_merge_NES | 北と東から入り、南へ合流して出る |
| river_source_S | 中央付近に控えめな水源があり、南へ出る |

これは実験の提案セットであり、既存プリセットの保存IDではない。6枚で接続一式が完成するという意味でもない。色と読みやすさを選んでから、採用するグラフで必要な形と流向へ拡張する。

## 彩度・明度・密度の実験

最初は草原1枚の構図を基準に、彩度だけを3条件で比較する。生成の揺らぎがあるので、独立生成3枚では彩度以外の差も混ざる。できれば同じ基準画像を添付して、色のみを変える編集指示で比較する。それでも形が変わったか目視確認する。

```text
添付画像を編集してください。構図、草の位置と形、大きさ、影の方向、
明度関係、タイルの境界を維持し、彩度だけを変更してください。
［ここへ下記の彩度指定を1つ入れる］
新しい物体や細部を追加せず、背景の明るさを変えないでください。
```

| 条件 | 差し替える彩度指定 |
|---|---|
| 控えめ | 彩度を低めにし、灰みを含む自然な緑にする。草と地面の区別は残す |
| 中間 | 自然な緑の色味を残しつつ、鮮烈な黄緑と黄色の強調を抑える |
| 鮮やか | 緑の彩度を高めて明快な色にする。明度とコントラストは維持する |

彩度を選んだ後、同じ彩度で草の密度を「まばら／中程度」、必要なら明暗差を「弱め／標準」で比較する。一度に全条件を掛け合わせない。

道・川は選んだ草原を背景参照にし、道の茶色・水の青緑の強さを別に調整する。水まで彩度を下げすぎて草と区別できなくしない。

## 採用判断の観点

1. 64px実寸で地形を判別できるか。
2. 駒の輪郭・陣営色が埋もれないか。
3. 移動範囲・選択マス等の実ゲーム表示が読めるか。
4. 複数タイルを並べて継ぎ目・同じ模様の反復が目立たないか。
5. 道・川の接続位置と幅が一致し、論理MAPと矛盾しないか。

入力・生成プロンプト・出力設定を候補ごとに残し、GUIの変換方法と色数を固定して比較する。単体画像としての鮮やかさだけで選ばず、ゲーム画面上で判断する。
