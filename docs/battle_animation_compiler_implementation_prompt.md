# 戦闘アニメーションCompiler：実装担当向けプロンプト

作成日：2026-09-08。これは後続実装用の依頼文であり、この文書の保存時点では実装していない。

## 依頼

SRPG戦闘アニメーション向けにCharacter Compilerを拡張してください。
正本は[仕様書](spec/battle_animation_compiler_spec.md)、判断理由は[ADR-0006](adr/0006-battle-animation-coordinate-and-detail-contract.md)です。
P0 → P1 → P2の順に実装・検証し、未確定の品質値は比較実験で決めてください。既存の機構を再利用し、同じ機能を別系統に作り直さないでください。

## 最初に確認すること

1. cwd、AGENTS.md、作業差分、利用可能なPythonを確認。原画と無関係な変更を保持。
2. `fable-judgment`、`tdd-first`を読み、受け入れ条件に対応する失敗テストから開始。
3. `config.py`、`pixelizer/character_animation.py`、`pixelizer/character.py`、`pixelizer/character_detail.py`、`pixelizer/palette.py`、`sheet/alpha_projection.py`、CLIとGUIの呼出しを確認。
4. `tests/test_canvas_spec.py`、`test_character_animation.py`、`test_character_detail.py`、`test_alpha_projection.py`の既存契約を確認。
5. ADR-0004/0005と旧待機仕様は背景資料。現在のコードと今回の仕様を照合し、古い「未実装」を現在の事実として扱わない。

2026-09-08の読取では、Coreの長方形Canvas・4〜64色・動作内union共通倍率は既に存在します。今回の主差分は移動保存、原点指定、動作間縮尺の再利用、共有palette、細部保護です。

## P0：共通変換で長方形の戦闘アニメを出す

- 既存Canvasを使用し、256×192、512×320、257×193などで原画から直接出力。
- 待機互換経路を維持し、戦闘用の移動保存モードを明示的に追加。
- 共通ソース原点・出力原点・等方倍率を解決する責務と、raster処理を分離。
- 原点は明示指定を先に実装。各frameのbbox底辺を足として自動採用しない。
- 全frameで同じサンプリング位相を使い、武器の張り出しで個別倍率を変えない。ジャンプを地面へ戻さない。
- 原点相対の左右上下の張り出しでfitし、輪郭とoffsetを含む見切れを検査。
- GUI/CLIは同じ設定へ接続。幅高さ・ガイド上の原点指定・出力先・エラーを提供。GUI作業時は`ui-design-system`を使用。
- 既存ログ・CI・NOTICE生成・保存復旧を利用し、独立した基盤を追加しない。

## P1：動作間の縮尺と色の統一

- 明示基準長または既知倍率を保存・再利用。異なる入力密度をbboxの高さから推測しない。
- 個別trim済みframeは明示登録原点で共通座標へ戻す。欠けた座標情報を生成しない。
- 動作全体の縮小済み可視画素から共有paletteを一度抽出し、全frameへ適用。
- 24/36/48/64色を比較可能にする。既存64色上限を広げる必要はない。輪郭色も上限に含める。
- 最終PNGから実palette、alpha、bbox、hashを計測。設定再読込で同じ出力を再現。

## P2：必要な1pxを保護し、効果を比較する

- 低コントラスト小成分の整理を既存ロジックから拡張し、明示mask・輪郭・線の接続を保護。
- alpha前処理での成分削除にも保護を通す。消失後の復元と、存在する画素の保護を混同しない。
- Canvasの余白だけ増やしても同じ身体倍率ならdetail結果を変えない。
- 元画像の特徴が縮小で消える場合は観測・警告。自動描き足しやフレーム対応推定は本段階に含めない。
- 単純縮小＋減色／新方式／各処理OFFを同じ素材・条件で比較。機械的整合性と人間による採用判断を別に報告。

## 受け入れ・禁止事項

- 仕様7節のテストを各段階で先に作り、既存テストで証明できる部分は再利用する。
- 64/128の既存出力、待機経路、MAPの64pxセル契約を維持する。
- フレームごとの再fit、移動保存モードでの最下端再配置、64px完成画像からのNative高解像度生成をしない。
- 色数は上限。未使用色の水増し、実測していない指標の合格化、全キャラ共通の最適値の断定をしない。
- 座標はleft/top含む、right/bottom含まない。接地境界と最後の可視画素行を区別する。
- 原画にある移動と明示offsetを二重適用しない。固定倍率の見切れを黙って縮小で回避しない。
- 新規依存・モデル導入、Quilting修正、MAP再設計、コミット・プッシュはこのプロンプトの範囲に含めない。
- 未確定値はRC一覧へ結果を追記。実装で解決できる選択は理由を残して進め、利用者の意図・入力情報が不可欠な箇所だけ確認する。

## 検証と完了報告

Pythonは実環境を確認し、既存の `py -3.10 -m pytest` 系のfocused testから実行してください。通常の検証を無条件に全体リリースゲートへ広げないでください。
日本語はUTF-8で編集し、差分・U+FFFD・関連文書リンクを確認。
完了報告には変更した動作、実行したテスト、再現fixture、実素材の比較結果または未実施、残るRC、規模見積りとの差を記載してください。合格は観測した範囲に限定してください。
