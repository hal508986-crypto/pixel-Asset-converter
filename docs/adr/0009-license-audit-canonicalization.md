# ADR-0009: ライセンス監査の主ライセンス表記を固定する

- 状態: Accepted
- 決定日: 2026-09-09
- 関連: [ライセンス監査ポリシー](../../LICENSE/audit-policy.json)、[監査生成器](../../scripts/generate_licenses.py)

## 背景

GitHub Actionsでは固定した依存バージョンを使っているが、Pythonの配布メタデータとwheel内のNOTICEは、同じ依存でも版やビルドによって表記が変わる。例えばNumPyは、主ライセンスを `BSD-3-Clause` としながら、PEP 639の式で同梱コンポーネントまで列挙する版がある。またGCCランタイムの例外は、`GPL-3.0-with-GCC-exception` と `GPL-3.0-or-later WITH GCC-exception-3.1` の両方の表記が存在する。

配布物の主ライセンスと同梱コンポーネントのライセンスを単純に連結すると、環境差で監査結果が変わり、コミット済み生成物の再現性ゲートがGitHubで落ちる。一方で、同梱コンポーネントの記録を捨てると、条件付きライセンスの確認漏れになる。

## 決定

1. `numpy`、`scipy`、`scikit-image`、`opencv-python` は、配布物そのものの主ライセンスを `LICENSE/audit-policy.json` の `package_spdx_overrides` で明示する。配布物の主ライセンス判定に、同梱コンポーネントのNOTICE表記を混ぜない。
2. GCCランタイム例外の既知の表記差は、監査内部で `GPL-3.0-with-GCC-exception` へ正規化する。これは同梱ライセンス識別子の表示と条件付き判定だけに適用し、主ライセンスを許可へ変更するものではない。
3. 固定依存ファイルとコミット済みライセンス生成物の再現性ゲートは維持する。テストを環境差に合わせて緩めず、主ライセンスのポリシーと同梱ライセンスの可視性をそれぞれ検査する。

## 却下した案

- 配布メタデータのSPDX式をそのまま主ライセンスとして採用する案は、同梱コンポーネント列挙を主ライセンスと誤認するため採用しない。
- 版ごとにテストの期待値を変える案は、GitHubと開発環境で監査基準が揺れるため採用しない。
- GCC例外の表記を未知として隠す案は、条件付きライセンスの見落としにつながるため採用しない。

## 影響

依存を追加・更新するときは、主ライセンスのポリシーoverrideが引き続き正しいかを再確認する必要がある。生成物には実際に検出したライセンス文書と同梱識別子を残すため、法的確認に必要な証跡は維持される。監査結果はPython 3.10の固定依存環境で安定して再生成できる。

## 検証

GCC例外表記の正規化、版依存のNumPyメタデータに対する主ライセンスoverride、同梱ライセンスの可視性をpytestで確認する。GitHub Actionsと同じPython 3.10・`requirements-license-audit.txt` 環境で、`scripts/generate_licenses.py --check`、ライセンスゲート、全pytestを実行する。
