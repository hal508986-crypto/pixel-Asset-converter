# アルファ連結成分によるアニメーション分割の救済設計

## 0. 実装担当への前提

本書は設計書であり、記載する追加機能は未実装。
[行別分割仕様](battle_animation_row_split_spec.md)で将来対象としていた「離れたエフェクトのグループ化、手動所属指定」を具体化する。
既存方式の契約は維持し、新しい成分分割についてのみ、本書の画素所有権・抽出・診断契約を優先する。
[戦闘アニメーション仕様](battle_animation_compiler_spec.md)の共通変換、共有パレット、出力命名を継承する。

- G-1: 3節の範囲内で実装する。元絵の補筆や意味的な人物認識へ拡張しない。
- G-2: 受け入れ条件に対応する失敗テストを先に作り、最小実装後に責務分離を確認する。
- G-3/G-4: 新規依存・モデル・素材・フォントはゼロ。既存の画像処理基盤を使う。
- G-5: 範囲・予算・判定規則の変更は本書を更新してから実装する。
- `fable-judgment`、コード変更時の `tdd-first`、適用される `AGENTS.md` を確認する。
- 元絵・既存出力・他者の変更を保持する。実素材検証は別出力先で行う。
- 幾何的な分離可能性と、エフェクトの意味的な所属の正しさを区別する。
- 「全成分を明示確認しなければコンパイルできない」という条件は撤回し、画素の欠落・重複ゼロは内部検査で保証する。利用者が扱う単位はコマである。
- 本書作成の依頼は、コード実装・コミット・プッシュの依頼を含まない。

## 1. 概要と1動作デモ

縦の透明な隙間がなくても、アルファ画素が別々の連結成分なら、成分ごとのマスクでコマを取り出す。
矩形の重なりを許しつつ、隣コマの画素混入・半透明の切り捨て・重複を防ぐ。
利用者が扱う単位はコマであり、微小成分の手動分類ではなく「指定コマ数の抽出」を主目的とする。

基本ワークフロー:
1. 各行の主要な塊から、指定コマ数の本体候補（主要成分）を作る。
2. 周辺の微小成分や低アルファ画素を、最近傍距離変換等によりコマ候補へまとめて安定的に仮所属させる。
3. F1〜Fnの抽出プレビューを表示し、利用者はコマ単位で元絵・抽出結果・疑わしい領域を確認する。
4. 問題がある成分・領域のみ、元絵上のクリックまたは矩形選択でまとめて所属先Fnを修正する。
5. 全コマを確認後、一括確定してコンパイルする。

デモ: 元絵を読み込み → 4列×3行と「透明部分＋絵のつながりで分割」を選択 → 透明帯では3コマとなる2行目を成分で4コマに分離 → F1〜F12の抽出プレビューで離れたエフェクトや疑わしい領域を確認 → 必要に応じて領域選択で所属修正 → 一括確定・コンパイル → `final_frames/F1.png`〜`F12.png`を確認する。
このデモの成功は未検証。下記の実測は主要成分が分離していることまでを示す。

## 2. ユーザー像と痛み

透明背景の生成アニメーションをコンパイルし、連番PNGとして編集・利用するユーザー。
横幅の大きい斬撃と隣のコマがX方向で重なるだけで、自動分割が失敗する。
手作業で原画を並べ替える代わりに、コンパイラ側で分離可能な画素を取り出したい。
販売形態・価格・利用者の支払い意欲の推測は本設計には不要。

## 5. アーキテクチャと動作契約

| `cli.py` | 新モード・所属ファイルの受け渡し、未解決時の診断と非成功終了 |

### 5.2 モードと互換性

- 新規明示モード: `row_alpha_components`。GUI名案: 「透明部分＋絵のつながりで分割」。
- 既存 `row_alpha_gap` は厳密な透明帯分割として維持する。既存設定を勝手に置き換えない。
- 新モードは最初に行を検出する。各行で従来の透明帯抽出を試し、不成功または保存用マスクを切断する行だけ成分方式へ進む。
- 成功した行と救済した行を混在できる。ただし全行に5.3節の画素保存検査を適用する。
- `fixed_grid` と `alpha_gap_auto` の既存結果は変更しない。
- P1で `hybrid` の順を「既存自動 → 行別透明帯 → 新方式 → 等分割」とする。
- 新方式が確認待ちの候補を返した場合は、hybridでも確認待ちを伝播し、等分割へ進まない。GUIは候補を表示し、CLIは診断を返す。
- 新方式が対象外の場合だけ既存の等分割fallbackへ進める。理由と既存の切断警告を必ず残す。確認待ちと対象外を同じ例外で処理しない。
- 総数は指定rows×columns。行優先、各行左から右の順でF1〜Fn。期待数に合わせて切断・成分削除をしない。

### 5.3 検出用マスクと保存用マスク

検出用 `D` は既存alphaしきい値・微小成分除去を利用し、行候補と主要成分候補を探すために使う。
保存用 `V = (alpha > 0)` は元画像全体から作り、微小成分除去をしない。成分の切断可否と画素所有権はVを正本とする。
alpha_threshold=0でもDに完全透明画素を含めないよう、新方式ではDをVと交差させる。

1. Vを全画像で8近傍ラベリングする。ラベルIDは走査順（上から下、左から右）で決定する。
2. Dから既存のY帯検出規則でrows個の行候補を得る。候補数不一致は対象外。
3. 行間の候補ガターから、Vの連結を切らない水平境界を既存の中央優先規則で選ぶ。低alphaがあるからといって消して境界を作らない。
4. 安全な境界がない場合は対象外。行をまたぐ成分を切断しない。外周は画像の0/W/Hで、center_cropしない。
5. 各V成分は必ず一つの行に丸ごと属する。行別に再ラベリングして接触を隠さない。

各可視画素pについて所有先 `owner(p)` を一つだけ持つ。完了時はV上に未割当・複数割当がゼロであること。
抽出した画素を元座標に戻すと、V上のRGBAが元画像と完全一致すること。alpha=0の隠れたRGBは復元契約に含めない。
細部削減・二値化・縮小は後段の既存処理。分割の画素保存と最終PNGの見た目保持は別々に検証する。

### 5.4 主要成分と周辺成分の扱い（コマ単位ワークフロー）

連結成分は人物でもコマでもない。大きなエフェクトが本体より広い場合もあるため、「面積上位N個＝正解」として無条件に確定しない。
利用者が扱う単位はコマであり、全成分を手動分類するのではなく、「各行の指定コマ数の本体候補作成 → 周辺の安定仮所属 → コマプレビュー → コマ単位確認・修正 → 一括確定」を行う。

**本体候補（主要成分）の生成規則:**
1. 各行について、検出用マスク `D` (`alpha >= alpha_threshold` かつ微小成分除去後) の連結成分を抽出する。
2. 他の行のコマを所属候補に混ぜず、行内の成分規模（面積・画素数）、位置、実画素間距離を使い、各行 `columns` 個の本体候補（シード）を決定的・説明可能に特定する。
3. 行内の本体候補を X中心（またはbbox左端）順に並べ、行内の左から右へ F1〜Fn の本体シードとする。
4. 主要候補不足や過密接触でコマを自動分解できない場合は、「○行目の本体候補不足／接触」として該当行・コマの問題を表示し、微小粒の一覧へ誘導しない。
5. 面積・距離等の規則は画像サイズ依存を考慮し、特定画像の座標や成分IDをハードコードしない。

**周辺成分・低アルファ画素の自動仮所属規則:**
1. 各行内の本体シードに対し、実画素間距離（ユークリッド距離二乗 / `cv2.distanceTransform`）を計算する。
2. 保存対象 `V = (alpha > 0)` のすべての可視画素を、最も近い本体シードのコマへ自動的に仮所属させる。
3. 同距離や弱い根拠の所属も、決定的な安定規則（X中心との近さ、左側コマ優先等）で仮配置し、未指定の大量発生で操作を止めない。
4. ただし、仮所属は確定済み・意味的に正しいとは扱わない。以下の条件を満たす成分・領域を「疑わしい領域（Suspicious Areas）」として記録・強調表示する:
   - **境界近傍成分 (border_proximity):** 複数の本体候補との最短距離比が近い成分（所属の境界線上にある成分）。
   - **遠隔大成分 (remote_large_satellite):** 本体から一定距離以上離れているが、面積が大きい成分（残像、飛翔武器、飛び散る大きなエフェクト等）。
   - **低アルファ接続領域 (low_alpha_bridge):** `V` では連結しているが `D` では別体であり、距離変換によって分割された境界画素群。
   - **同距離候補 (equidistant_candidates):** 複数のコマへの最短距離が同一の成分。
5. 画素の欠落・重複ゼロは、内部検査（V上のRGBA完全一致、未割当0、重複0）で保証する。

**コマ単位の確認と領域修正:**
1. 利用者は全成分を個別に選ぶ必要はなく、生成された F1〜Fn の抽出プレビュー（12コマ）を確認する。
2. 疑わしい領域が強調表示されるため、問題がある箇所のみ元絵上で「成分クリック」または「矩形で複数成分を選択」し、まとめて所属先 Fn を変更する。
3. 元絵の成分を選択した際は現在の仮所属先を表示し、主要候補の変更も元絵上の操作で行える。
4. 所属変更時には、所有マスク、抽出プレビュー、原点整合を即座に再計算し、古い確認状態を使わない。
5. 全コマを確認後、一括確定してコンパイルへ進む。

### 5.5 抽出と座標登録

- コマiの所有マスク `M_i` は、割り当てたV成分・画素の和集合。`M_i & M_j` は常に空。
- `source_box` はM_iの可視bboxとする。矩形同士の重複を許す。既存の「矩形が元画像全域を分担する」契約は新方式には適用しない。
- `source.crop(source_box)`だけでは抽出しない。矩形内のM_i以外を透明化し、M_i内のRGBAはそのままコピーする。
- `content_box` は所有画素のbbox。bbox外の画素を所属候補から取りこぼさない。
- 論理原点 `L_i=(round(column*W/columns), round(row*H/rows))` を継承する。Pythonのround規約をテストで固定する。
- 切り出し左上C_i、抽出内座標uに対して論理座標は `q=u+C_i-L_i`。`registration_translation=C_i-L_i`。
- 負座標を許し、共通作業キャンバスと既存共通倍率を使う。bboxを個別中央寄せして動きを変えない。
- `legacy_foot` / `preserve_motion`、原点・offset・共有パレットの既存意味は維持する。
- 成功した透明帯行も、新方式ではVに基づく所有権を作る。矩形cropを互換経路として使う場合も、V上の欠落・重複ゼロを検証する。

### 5.6 GUI・操作系と保護マスク

- **数千件のコンボボックス撤去:** 通常画面から成分ごとのコンボボックス一覧を撤去する。詳細な成分ID一覧は診断用に残せるが、通常操作の必須経路にしない。
- **F1〜Fn抽出プレビューグリッド:** 主画面に全コマ（例: 12コマ）の抽出プレビューを並べ、元絵と抽出結果を直接照合できるようにする。半透明の裾、エフェクト、隣コマ混入を視覚的に確認できる。
- **疑わしい領域の強調と誘導:** 疑わしい領域（境界近傍、遠隔残像等）をハイライトし、該当するコマへワンクリックで注目できるようにする。
- **元絵上での複数成分選択・所属修正:** 元絵プレビュー上で「成分をクリック」または「矩形ドラッグで複数成分を選択」し、選択した成分の所属先 Fn をまとめて変更する。
- **一括確定:** 全コマを確認したら「一括確定」ボタンで確定状態へ遷移し、コンパイルを実行できる。
- **レスポンシブ配置:** 狭いウィンドウでもプレビュー、所属修正、確定、コンパイルボタンへスクロールや破綻なく到達できるようにUI/UXを整える。

現行の `map_source_point_to_frame` は矩形を順に探索するため、重複bboxで誤ったコマを選ぶ。
新方式では所有マスクを受け取れる経路を追加し、V上のクリックはownerからコマを決める。
透明な場所を原点にしたい場合は、先に対象Fnを選択してから点を指定する。重複矩形の先頭へ暗黙に割り当てない。
旧モードの矩形だけのAPIは互換維持し、新方式の呼び出し元は必ず所有権を渡す。

保護マスクは選択フレームと同じC_i/L_iで変換し、画素保護はM_iとの交差だけに適用する。
元画像座標の保護指定を隣コマへ複製しない。保護指定は成分を分割・生成する指示にはしない。
現行 `_split_character_animation_source` には保護マスク引数がないため、分割へ既に渡っていると仮定しない。
新方式はVを保存するので、低alphaの保護対象を分割時に消す必要はない。後段の保護処理への座標変換を検証する。

### 5.7 結果型とレポート

分割の解析段階に `resolved` / `needs_assignment` / `unsupported` を区別する内部結果を設ける。
`needs_assignment` は候補・理由を持ち、コンパイル成功結果とは別物にする。未解決のまま `SpriteSheetSplitResult.frames` を完成品として返さない。

新方式の成功結果では `detected_mode="row_alpha_components"`、行ごとの `extraction_method` を記録する。
実行時の所有ラベル配列を共有し、毎フレーム画像全体のbool配列を保持しない。
レポートは新方式について `schema_version=4`（外側bbox_reportと内側sprite_sheet_split）とし、既存方式の3は維持する。読取側は3/4を受け付け、未知版は明示エラー。

追加データ:

| 項目 | 内容 |
|---|---|
| `extraction_kind` | 新方式は `component_mask`。source_boxのみで再抽出できないことを明示 |
| `components` | ID、行、面積、検出画素数、bbox、所属frame_id、決定根拠 |
| `row_methods` | 行、`alpha_gap`または`components`、試行結果・理由 |
| `ownership_validation` | 保存対象数、割当数、未割当数、重複数、RGBA不一致数 |
| `assignment_status` | `geometric`または`user_confirmed`。意味的正解確率にはしない |
| `assignment_source` | 自動限定条件、GUI確認、所属ファイルの別 |
| `mask_encoding` | 各セル内の所有画素を行ごとの半開区間 `[y,x_start,x_end]` で保存するRLE、版1 |

RLE座標はsource_box左上からのローカル整数座標。y、x_start順に整列し、範囲外・重複区間を拒否する。
セルごとのRLEからM_iを復元でき、元画像hashと組み合わせて抽出を再現できること。
新方式の共通 `x_bands` は空。既存 `row_bands` のX帯に重複bboxを透明帯として偽装しない。
`cells`、`row_methods`、所有権を参照するよう読取側を更新する。

`quality_status` は既存のpassed/warningを維持する。所有権検査に合格した明示モードはpassedとできるが、初回表示には「所属はプレビューで確認してください」を付ける。
hybridで新方式を使った場合は救済使用をwarningとして残す。confidenceは新方式では幾何検査の合否を表す1.0/0.0のみで、所属確率として表示しない。
`boundary_crossings=[]` だけを画素保存の証拠にしない。新方式の保証はownership_validationで示す。

## 8. データとファイル配置

- 最終出力は既存 `final_frames/Fn.png`、`aligned_sheet.png`、`compiled_sheet.png`、`bbox_report.json` を維持する。
- `detection_overlay.png` は新方式で所有成分をコマごとに色分けする。bbox枠だけで分離成功を示さない。
- 未解決プレビューはGUIのメモリ上に保持する。失敗した診断で既存の正常出力を置換しない。
- P1で所属指定ファイル `component_assignments.json` を、利用者が見える保存ダイアログから明示保存・読込できるようにする。既存出力へ自動保存しない。
- CLI引数案は `--component-assignments PATH`。GUI/CLIともCoreの同じ検証を通す。
- 所属ファイルは版1、入力SHA-256、寸法、rows/columns、検出設定一式、ラベル規則版、全成分ID→frame_idの対応を保存する。
- 入力や設定が一致しない場合は再解析・再確認を要求する。古いIDを近い位置へ自動で付け替えない。
- レポートに保存したRLEは抽出結果の証跡。所属ファイルは再実行の入力であり、両者を同一スキーマとして扱わない。
- 設定保存先・アンインストール挙動は変更なし。
