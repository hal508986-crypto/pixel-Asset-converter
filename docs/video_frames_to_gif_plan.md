## 1. 目的とスコープ

MiniMax H3（ローカルのComfyUI経由）が出力した、24fpsの連番PNG（数十枚）を、

```text
連番PNG → 背景除去 → 共通座標・共有パレットでコンパイル → 透過GIF
```

まで一気通貫で行う。途中成果物は全段階を個別ファイルで残す。

### 確定した前提（ユーザー確認済み）

- 背景は**単色（緑または白）で、透過ではない**。生成側である程度調整できる。
- 出力サイズは**512基準**。ただし64〜512を柔軟に扱えること。
- 出力は**まずGIFのみ**。APNGは後続（Pillowだけで出せるため追加は軽い）。
- H3側の成果物はまだ無い。開発は疑似連番で進める。

### スコープ外（初期実装では扱わない）

- MP4デコード入力（opencvは既に依存にあるので後から追加可能）
- ちらつき抑制・動き推定・AI動画の造形修復
- GUI対応（`gui/main_window.py` は2890行あり、CLIで通した後に扱う）

## 2. 実現性の裏取り（調査結果）

- `align_character_frames()` は Sheet なしで画像リストを受けられる。共通座標・倍率（`CharacterAnimationTransform`）、`preserve_motion`、共有パレットの足場がある。**作り直しは不要**。
- 整列以降の処理（`_compile_character_animation_to_root` の `prepared` 以降）は既にフレーム単位。入口がSheet分割に密結合しているだけ。
- Pillowのみで透過GIFを書ける。合成48フレーム（24fps）を書き出して再読込し、可視RGB・アルファが全フレームで完全一致することを確認済み。
- 24fpsの1フレームは41.67msで、GIFは10ms刻み。累積丸め（40,40,40,50ms…）で48フレームの合計がちょうど2000msになる。
- 既存のアニメ系テストは 36 passed / 5 skipped（依存導入後）。

## 3. 注意点・リスク

1. **背景除去が必須**: アニメ経路は内部で `background_mode="alpha"` 固定。不透明なPNGをそのまま通すと画面全体がキャラ扱いになり、共通bboxが壊れる。
   - `preprocess/background.py` の `apply_background`（`color`/`auto`、境界連結の塗りつぶし）を流用できる。
   - フレームごとに背景色を自動判定すると判定が揺れる。**背景色は連番全体で1回決めて共有**する。
   - 緑背景は、キャラの縁に緑が滲む（スピル）可能性がある。白背景は、キャラ内部の白を消さないこと（境界連結なので内部は残る想定）。どちらも実素材で確認する。
2. **Sheet総画素の上限**: `MAX_ANIMATION_OUTPUT_SHEET_PIXELS = 16,777,216`。512×512×64枚でちょうど上限。512基準では、Sheet合成を通さない連番専用経路が必要。
3. **連番ファイル名**: 既存の `F1, F2, …, F10` はソート順が崩れる。連番経路はゼロ埋め（`F001`）にする。
4. **ちらつきの発生源（推測。実素材で計測して確定する）**:
   - 縮小が `_sample_nearest`（最近傍）。H3解像度から64pxへは縮小率が大きい。
   - フレームごとの孤立成分除去・ディテール整理。
   - GIF保存（二値透明、10ms刻み）。
5. **GIFの制約**: 二値透明、パレット最大256色（本製品は最大64色なので余裕）。正本はPNG連番、GIFは派生物とする。

## 4. 設計方針

```text
Sheet入力 ─→ 分割 ──┐
                    ├→ 共通のフレーム列コンパイル → PNG連番 ─→ GIF
連番PNG入力 ─→ 読込 ─┘        （背景除去は連番入力のみ）
```

- 既存の単体PNGコンパイラと、Sheet経路の出力を保護する。動画対応のために核を置換しない。
- 連番入力では `preserve_motion` を既定とし、跳躍・突進を足元固定で消さない。
- 決定論を維持する（走査順・同点処理・丸め規則を固定）。
- 出力サイズは `canvas_size` で64〜512（以上）を指定可能とする。既存の出力Canvas上限（1280）の範囲内。

## 5. 中間成果物のレイアウト（案）

```text
<output>/
  source_frames/      入力PNGの不変コピー（ゼロ埋め連番）
```

## 追記: 実素材（デフォルメ素材）と「キャラを大きく」（fit_percentile）

- 素材: 頭身の低いデフォルメキャラ（73枚・512×512・青緑背景 `#51A2A2` を外周100%一致で推定）。パレット48色・許容差45・輪郭削り1で 256px に通して良好。
- 課題: 全フレームがはみ出さない倍率だと、槍を左へ突き出すコマ（約2割）と縦に立てるコマ（F056）が範囲を決め、キャラ本体が小さくなる（256pxで本体約143px）。
- 対応: `fit_percentile`（既定100＝従来どおり）。各フレームの原点からの張り出し（左・右・上）を百分位で測り、その割合のフレームが収まる最大の倍率にする。はみ出す極端なコマは見切れを許し、警告とレポート（`clipped`）に記録。原点の横位置は各フレームbbox中心の中央値。`CharacterAnimationConfig.allow_clipping` を追加（既定オフ。オンのときだけ `bbox_report.json` の config に出るので、Sheet経路の出力は不変）。
- 実測（この素材、256px）: 全フレームを収める場合 倍率0.48・本体約143px、上位70% 倍率0.757・本体約227px（約1.6倍）。70%で 33/73 フレームがどこかしら見切れる（大半は槍の先端）。
- 解像度比較（70%・48色）: 128px は粗い。256px は細部まで出る。512px は256pxと情報量がほぼ同じでドットが大きくなるだけ（元絵を約1.5倍に引き伸ばすため）。ファイルは 256:548KB / 512:1.4MB / 128:214KB。→ この素材では256pxがちょうどよい。
- 状態: コア・ジョブ層・CLI（`--fit-percentile`）まで。GUIへの追加（フレーミングの選択）は、方針の確認後。

## 追記: キャラの身長を基準にした大きさ決め（character_height / canvas_auto / trimmed）

- 背景: 全フレームを収める方式や百分位方式は、動作ごとに「極端なコマ」が違うため、同じキャラでも動作間でサイズが揃わない。また踏み込み・跳躍で縦幅が変わる動作では、フレーム単位で倍率を決めるとサイズがブレる。ユーザー方針: **基本は倍率と足元を固定**、最終的にAseprite等で手直しするので全フレーム同サイズのCanvasが主、ゲームエンジンは自作でアセットに合わせられる。
- 計測（本体の高さ＝開き処理で細い部分を除いた最大成分。元絵512px、73枚）: デフォルメ素材 ブレ0.8%（283〜293px）、リアル寄り素材 3.5%、最初の素材 12.4%（246〜359px。動画内のカメラ移動が原因）。全体のbbox幅は槍のせいで14〜23%ブレるので基準にならない。→ アルファから身長の基準は取れるが、元動画側でサイズが変わる素材では基準の選択（中央値/最初/フレーム番号）が要る。
- 実装: `pixelizer/character_body.py`（`measure_body`: 開き処理の直径は画像短辺の1/64で最小3px・奇数、最大の8連結成分。`reference_body_height`: median / first / N）。`character_frame_sequence._with_character_height`: 倍率＝指定の身長÷基準の本体高さ、足元＝各フレームの本体下端の中央値、横位置＝本体中心の中央値。Canvas固定なら収まらない部分は見切れを許し（警告・`clipped`）、Canvas自動なら全フレームの張り出しが収まる最小のCanvas（四方2px、上限4096）。`fit_percentile`・固定倍率とは同時に使えない。
- 切り詰め＋オフセット: `trimmed_frames/F001.png…` と `trim_manifest.json`（canvas_size / pivot / scale / fps / durations_ms / 各フレームの x,y,width,height,offset_from_pivot）。復元は最終フレームとピクセル一致（実素材73/73で確認）。切り詰めで面積は平均43%。既定オン（`--no-trim` で無効）。
- 実素材（デフォルメ素材、身長200px・48色）: Canvas自動 329×281px、出力のキャラ本体の高さ 平均200.3px（197〜202）、見切れ0コマ。Canvas固定256でも高さ199.8px（198〜202）、槍の先端で32コマが見切れる。従来（全フレームを収める256px）ではキャラ本体143pxだった。
- GUI: 「キャラの大きさ（フレーミング）」欄（全フレームが収まる〈従来・既定〉/ 上位N% / 身長指定）。身長指定では基準・基準フレーム番号・Canvas自動、Canvas自動のときは幅・高さが無効になる。切り詰め出力のチェック。結果表示に出力サイズと倍率。
- テスト: `tests/test_character_height.py`（9件: 本体計測、基準、倍率と足元、エラー、Canvas自動の最小性、パイプラインで「立ちは指定どおり・しゃがみは縦が縮む・足元は固定」、切り詰めの復元一致、マニフェスト、ジョブ/CLI）＋GUIテスト2件。Sheet経路の200ファイルのバイト一致を維持。
- 既定は従来どおり（全フレームが収まる）のまま。推奨（身長指定）を既定にするかは未決定。
