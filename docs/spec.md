# 美麗絵→ピクセルアート変換コンパイラ MVP仕様書（Python単体構成）

## 1. 文書概要

### 1.1 背景
高解像度の美麗なイラストを、そのまま縮小・減色するだけでは、良質なピクセルアート（ドット絵）にはならない。  
理由は、ピクセルアートが単なる低解像度画像ではなく、**限られた解像度・色数・1px単位の意味密度**を前提にした再構成表現だからである。

本仕様書は、以下の思想に基づくMVPの設計を定義する。

- 画像生成AIに最終ドット絵そのものを描かせるのではなく、**何を残し、何を捨て、何を誇張するか**を判断させる
- 実際のピクセル配置・減色・クラスタ整理は、**決定論的なアルゴリズム**に任せる
- すなわち、**画像→意味構造→ピクセルアート**という「コンパイラ」的変換として扱う

---

## 2. プロダクト定義

### 2.1 プロダクト名（仮）
Pixel Art Compiler  
略称案: `pac`, `pixel-compiler`, `dot-compiler`

### 2.2 一言定義
高解像度イラストを入力として受け取り、  
**意味解析 → 中間表現（IR） → 制約付きピクセル化 → ピクセル文法補正**  
を経て、手打ちに近い構造を持つピクセルアートへ変換するPython製ツール。

### 2.3 MVPの目的
MVPでは以下を達成する。

1. 1枚の人物イラストを入力できる
2. LLM/VLM補助あり・なしの両モードで中間表現を生成できる
3. 指定解像度（例: 16x16, 32x32, 64x64）と色数（例: 8, 16, 32色）に落とし込める
4. ピクセルアートとして最低限見栄えのする出力を得る
5. 各段階の中間成果物を確認できる
6. Codex等のLLMに対して、MCP経由で中間判断を委譲する構造を持てる

---

## 3. 設計思想

### 3.1 本ツールの核心
本ツールは、以下を前提とする。

- 単純な縮小はピクセルアート化ではない
- 単純な減色もピクセルアート化ではない
- ドット絵化の本質は、**意味的に重要な特徴を限られたpixel予算へ再符号化すること**である

### 3.2 基本仮説
変換の本質は以下の流れにある。

1. 元画像を解析する
2. 重要な要素と不要な要素を分離する
3. 残すべき特徴を抽象化する
4. 解像度・色数という制約の中でpixelへ再配置する
5. ピクセルアート特有の文法で整える

### 3.3 MVPとしての解釈
MVPでは、ドット絵化を次のパイプラインとして定義する。

- **意味解析**
- **表現予算決定**
- **減算**
- **抽象化**
- **制約付きピクセル化**
- **ピクセル文法補正**
- **出力**

## 5. 想定ユースケース

### 5.1 基本ユースケース
ユーザーが立ち絵イラストを1枚入力し、以下を指定する。

- 出力サイズ: 32x32 / 32x48 / 64x64
- パレット数: 16色
- 背景処理: 透過
- スタイル方針: 「輪郭重視」「顔重視」「シルエット重視」等

その後、ツールが以下を実行する。

- 画像解析
- 重要領域抽出
- IR生成
- ピクセル化
- ピクセル補正
- 最終PNG出力

### 5.2 開発者ユースケース
開発者が中間IRや補正アルゴリズムを差し替え、  
複数の変換戦略を比較検証する。

## 6. システム全体アーキテクチャ

### 6.1 全体構成
```text
Input Image
   ↓
Preprocess
   ↓
CV Analysis
   ↓
Semantic Analysis (optional: LLM/VLM via MCP)
   ↓
Pixel Art IR
   ↓
Budget Allocation
   ↓
Pixelization Engine
   ↓
Pixel Grammar Postprocess
   ↓
Exporter
```

### 6.2 モジュール構成
- `io`  
  入出力、画像読込、設定読込、保存

- `preprocess`  
  リサイズ前処理、透過処理、ノイズ低減、背景分離補助

- `analysis.cv`  
  エッジ検出、セグメンテーション、色クラスタ、輪郭抽出、サリエンシー

- `analysis.semantic`  
  LLM/VLM連携、重要度推定、保持/削除/誇張方針の決定

- `ir`  
  Pixel Art IR 定義・生成・検証

- `allocator`  
  pixel予算、色予算、重要度に応じた領域配分

- `pixelizer`  
  制約付きラスタ化、減色、領域のpixel化

- `postprocess`  
  ジャギー補正、孤立pixel除去、輪郭調整、ディザ制御

- `ui`  
  CLI、および必要なら簡易GUI

- `mcp_client`  
  Codex等をMCP経由で呼び出すアダプタ

## 8. データモデル

### 8.1 基本概念
MVPの中核は、画像そのものではなく、**Pixel Art IR（中間表現）**を明示的に持つこと。

### 8.2 Pixel Art IR の役割
IRは以下を担う。

- 何が描かれているか
- どこが重要か
- 何を残すか
- 何を捨てるか
- 何を誇張してよいか
- どの領域にどれだけのpixel予算を割くか

### 8.3 IRの最小構造
```json
{
  "canvas": {
    "width": 32,
    "height": 48,
    "palette_budget": 16,
    "background": "transparent"
  },
  "global_style": {
    "priority": "silhouette_face_balance",
    "outline_mode": "selective",
    "dither_mode": "minimal"
  },
  "subjects": [
    {
      "id": "char_001",
      "type": "character",
      "importance": 1.0,
      "bbox": [0.12, 0.05, 0.78, 0.90],
      "regions": [
        {
          "name": "hair",
          "importance": 0.95,
          "preserve": ["silhouette", "dominant_color"],
          "discard": ["fine_strands"],
          "exaggerate": [],
          "color_hint": ["gold"],
          "pixel_budget_ratio": 0.18
        },
        {
          "name": "face",
          "importance": 1.0,
          "preserve": ["eyes", "face_shape"],
          "discard": ["skin_gradation"],
          "exaggerate": ["eyes"],
          "pixel_budget_ratio": 0.20
        },
        {
          "name": "cape",
          "importance": 0.88,
          "preserve": ["outer_shape", "red_identity"],
          "discard": ["small_folds"],
          "pixel_budget_ratio": 0.22
        }
      ]
    }
  ]
}
```

### 8.4 IRの設計原則
- 数学的厳密さよりも、変換アルゴリズムに必要な判断を運べることを優先
- LLMが生成しやすいJSON構造
- 決定論的アルゴリズムが解釈しやすい粒度
- 段階的に拡張可能

## 11. パイプライン仕様

## 11.1 Step 1: Preprocess
### 目的
解析しやすい入力へ整える。

### 処理内容
- 画像読込
- alpha正規化
- 背景色推定 / 背景分離補助
- 高周波ノイズ軽減
- 必要に応じた一時的な高解像度正規化

### MVP方針
- 透過PNGがある場合はそれを優先
- 透過でない場合は簡易背景除去または矩形前景抽出

---

## 11.2 Step 2: CV Analysis
### 目的
低レベル構造を抽出する。

### 抽出対象
- エッジ
- 輪郭
- 領域分割
- サリエンシー
- 支配色
- 明暗境界
- 顔領域候補
- 主要パーツ候補

### 候補アルゴリズム
- Canny edge
- SLIC superpixel
- k-means color clustering
- connected components
- morphological operations

### 出力
- エッジマップ
- 領域分割マップ
- 色クラスタ情報
- 主要輪郭候補

---

## 11.3 Step 3: Semantic Analysis
### 目的
「何を残し、何を捨てるか」を判断する。

### モード
1. **Rule-based mode**
2. **LLM-assisted mode**

### Rule-based mode
CV分析結果とヒューリスティクスだけで判断する。

例:
- 顔候補領域は重要度高
- 高コントラスト小領域は目候補として重要視
- 長辺方向に連なる外周はシルエット優先
- 領域内部の微細テクスチャは削除寄り

### LLM-assisted mode
MCP経由でCodex等に以下を依頼する。

#### 依頼内容
- 主題推定
- 領域ラベル付け
- 識別上の重要度推定
- preserve/discard/exaggerate の判断
- スタイル方針生成

#### 入力
- 画像そのもの、または中間解析要約
- 領域ごとの特徴量要約
- 期待する出力スキーマ

#### 出力
- JSON形式のPixel Art IR補助情報

### LLMの責務
- 意味判断
- 優先順位付け
- 抽象化方針決定

### LLMに任せないこと
- 最終pixel座標の決定
- パレット最終最適化
- 1px単位のクラスタ調整

---

## 11.4 Step 4: Budget Allocation
### 目的
限られたpixel数・色数を各領域へ配分する。

### 考え方
総pixel予算は固定されるため、すべてを均等に表現しない。

### 例
32x48 = 1536 pixel

- 顔: 20%
- 髪: 18%
- マント: 22%
- 武器: 15%
- 服本体: 15%
- 装飾: 5%
- その他: 5%

### 配分軸
- semantic importance
- シルエット寄与
- 色の識別性
- 面積
- 局所コントラスト
- 出力解像度

### MVP方針
まずはヒューリスティクスで配分し、後から改善可能にする。

---

## 11.5 Step 5: Pixelization Engine
### 目的
IRと配分情報をもとに、制約付きでピクセル化する。

### 処理内容
- 空間量子化
- 領域ごとのラスタ化
- パレット量子化
- 輪郭保持
- 重要パーツの最小表現保証

### 重要な制約
- 目などの重要パーツには最低pixel数を保証する
- 輪郭は可能な限り切れないようにする
- 色クラスタは単純平均で潰しすぎない
- 領域ごとに減色の優先度を変える

### 候補実装
- 基本縮小ではなく、
  - 領域単位縮小
  - 重要部位の局所再配分
  - 色数制約付き減色
  を組み合わせる

### MVP簡易戦略
1. 全体の粗い縮小
2. 領域別に再評価
3. 目・顔・武器などを局所補正
4. パレット再調整

---

## 11.6 Step 6: Pixel Grammar Postprocess
### 目的
「低解像度画像」ではなく「ドット絵」に近づける。

### 対象ルール
- 孤立pixelの除去
- 不自然な1pxノイズの削除
- ジャギーの整理
- 輪郭の明確化
- 選択的アンチエイリアス抑制
- ディザの量制御
- ピクセルクラスタのまとまり改善

### MVPで実装する補正
- isolated pixel removal
- 1px穴埋め
- 小さすぎる斜線の整理
- 外周輪郭補正
- 色クラスタの近似統合

---

## 11.7 Step 7: Export
### 出力
- PNG
- 透過PNG対応
- IR JSON
- 可視化成果物

---

## 12. LLM / Codex / MCP 連携仕様

### 12.1 目的
Codex等に、画像の意味解析や抽象化方針決定を委譲する。

### 12.2 連携の位置
- Preprocess後
- CV Analysis後
- IR生成時

### 12.3 役割
Codexには「コンパイラ本体」を書かせることもできるし、  
実行時に「この画像のIRを生成する補助」を担わせることもできる。

### 12.4 MVPでの使い分け
#### A. 開発フェーズ
- CodexにMCP経由で実装支援を依頼
- モジュールごとにコード生成
- テスト生成
- リファクタリング支援

#### B. 実行フェーズ
- Codex/VLMに中間判断を依頼
- JSONでIR補助情報を返させる

### 12.5 LLMに要求する出力スキーマ
- 厳格JSON
- 不明点は `unknown`
- 推定信頼度を付与
- preserve/discard/exaggerate を必須フィールド化

### 12.6 LLM呼び出し失敗時
- Rule-based fallback を使用
- 実行継続可能とする

## 25. 結論
本MVPは、単なる画像縮小ツールではなく、  
**美麗絵をピクセルアートへ変換する意味駆動型コンパイラ**として設計する。

その実現のために、

- AIは「意味判断」
- アルゴリズムは「制約付き描画」
- IRは「両者をつなぐ中間表現」

という役割分担を採用する。

これにより、生成AI単独では苦手な1px単位の表現制御と、  
純アルゴリズムだけでは弱い意味判断の両方を補完し合う構造を目指す。
