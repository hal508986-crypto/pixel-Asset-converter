## 1. 概要と1動作デモ

SRPGの戦闘アニメーション原画を、意図した移動・同一縮尺・画素の明瞭さを保ったフレーム群へ変換する。
元画像から直接、正方形または長方形の出力へ縮小し、共有色と必要な細部を制御する。
ここでのpixel perfectは整数画素への配置、二値アルファ、色数上限、最近傍表示を検証できることを指す。美的完成度や手打ち作品との同等性は保証しない。

デモ：武器を伸ばすフレームと跳躍フレームを含むシートを選ぶ → 幅256・高さ192、共通基準点、36色を指定 → 出力先を選び変換 → 地面ガイド付き連続表示で、身体がフレームごとに縮まず、跳躍が残ることを確認する。数値はデモ条件であり推奨値ではない。

## 2. ユーザー像と痛み

対象は生成原画などからSRPG戦闘アニメ素材を制作する利用者。個別リサイズでは剣・槍・マントの張り出しによって身体の大きさが変わり、底辺合わせでは跳躍が消える。色数・サイズ・細部整理を個別に調整する手間もある。販売形態や価格は今回決めない。

会話で確認された意図：256/512pxへの拡張、長方形を含む任意サイズ、36色以上の比較、必要な1pxの保持、動作単位の縮尺統一。
設計上の提案：基準点の明示指定を先に提供し、動作内と動作間の縮尺を分離する。自動の身体認識は前提にしない。

## 5. 契約とモジュール境界

### 5.1 出力と縮尺

- Canvasは幅W・高さHが正の整数。正方形、2の累乗、64の倍数へ限定しない。ゼロ・負数・小数・真偽値は拒否。
- 実用上限はRC-01で実測する。任意サイズは無制限メモリの保証ではない。出力前にフレーム数とプレビュー倍率を含む容量見積りを行う。
- Native出力は背景解決済み原画から直接行う。64/128の完成画像や解析用256px画像を512出力の中間ラスタにしない。
- 動作内の全フレームは同じ等方倍率sを使用する。横縦別倍率や各フレームbbox-fitは禁止。
- 自動fitは動作全体を収める。武器の大きな動作ほど動作全体が小さくなる可能性を表示し、動作間の身体サイズ一致とは区別する。
- 動作間を揃える場合は同じ縮尺設定を再利用する。入力の画素密度が違う場合、明示した基準長により校正する。基準長の自動推定はしない。
- 校正する場合は `s_action = target_reference_length / source_reference_length`。基準長は正値で、どの部位・区間を測ったか記録する。ポーズごとに変化するbbox高を身体の基準長とみなさない。
- 拡大は既存互換経路を維持し、新モードでは明示選択と記録を必要とする。細部の増加を保証しない。

### 5.2 座標と基準点

座標は左上原点、x右向き・y下向き、単位はpx。bboxはright/bottomを含まない。地面は画素行番号ではなく境界座標で表す。地面Gに接する最後の画素行はG-1。

新しい配置モードを待機互換モードと分離する。

1. **待機互換**：現行の足元合わせを保持。既存無指定入力の出力を変えない。
2. **移動保存**：動作共通のソース原点O、出力原点Aを一度解決し、すべてのフレームへ同じ変換を適用。個別bottomで再配置しない。

概念式：`q = A + s * (p - O) + d_i`。
`d_i` は出力px単位の明示整数オフセットで、未指定は0。ソース内にある移動を式が既に保持するため、同じ移動を二重に加算しない。欠落値と指定0をレポート上で区別する。

元セルの位置関係が保たれた入力をP0の対象とする。シート分割は元セルの座標・crop offsetを保持し、独立trimで失った位置を推測しない。個別trim済み入力は、P1の明示登録原点で共通座標へ戻してから処理する。情報がなければ「基準点が必要」とする。

原点Oの明示指定は、足より下へ伸びる剣・マントにも対応する。未指定時は新モードの変換を開始せず、GUIでガイド付き指定／CLIで必要項目を案内する。自動bbox底辺を足として確定しない。

自動fitはOに対する全可視範囲の左右上下の張り出しと、AからCanvas各辺までの余裕を比較し、輪郭幅・オフセットも含めて全フレームが収まる最大の等方倍率を選ぶ。負の利用可能幅や配置不能はエラー。単なるunion幅・高さだけで片側の見切れを見逃さない。

固定倍率で収まらなければ、必要Canvas寸法と不足する辺を報告する。黙って縮小・切り取りしない。利用者がCanvasまたは倍率を変更する。

最近傍サンプリングは動作共通の変換・サンプリング位相を使う。独立cropの丸めで位相を変えない。境界の整数化はfloor(v+0.5)を使い、負座標・奇数寸法をテストする。実装の逆写像と画素中心規約はP0で固定し、対応表をテストへ残す。連続座標の移動量は量子化されるため、任意倍率で無揺れを保証せず丸め誤差を報告する。

### 5.3 Paletteと細部

- Canvasと色数・detail presetは独立。既存B24を上書きしない。色数は上限であり、足りない色を水増ししない。
- P1は既存4〜64色を使う。128で24/36、256で24/36/48、512で36/48/64を比較候補にする。推奨値はRC-02で決める。
- 共有paletteは同じ動作の縮小・色調整済み可視画素をフレーム順に集め、一度だけ抽出する。固定palette入力があれば再学習しない。
- 全フレームの最終可視RGBの和集合が予算以下かつ共有paletteの部分集合であること。輪郭色も予算に含める。透明RGBを学習対象にしない。
- 共有paletteだけで部位の色固定やちらつき解消を保証しない。原画の色変動は別に観測する。
- P2の「必要な1px」は出力画素を指す。面積だけで削除しない。明示保護mask、シルエット、高コントラスト、細線接続を保持候補とする。
- 明示保護maskはソースと同じ座標を持ち、同じ変換で出力へ写す。保護部分が縮小で消えた場合は記録・警告する。無断の再描画はしない。
- 前処理のalpha孤立成分削除と減色後のRGB成分整理を区別する。前者で消した画素は後者で復活できない。新モードでは保護対象を前処理でも除外し、削除差分を保存する。
- 接続はP2で4/8近傍を区別し、斜線も含むfixtureで規約を固定する。色を置き換えて重要な細線を分断しない。高コントラストの点をすべて「目」と推定しない。
- 面積閾値をCanvas寸法だけで比例拡大しない。身体縮尺が同じで余白だけ増えた場合、detail結果は同じであること。既存方式は互換モードに残し、新方式の閾値はRC-03で比較する。

## 8. データとファイル配置

保存先は利用者が指定しGUIでも表示・変更できる。入力と同じファイルを上書きしない。既存のstaging・復旧処理を再利用する。
フレームPNG、結合シート、等倍・整数倍プレビュー、設定、検証レポートを出す。大きい画像へ固定8倍プレビューを無条件生成しない。
レポートにはschema version、入力hash、frame順、Canvas、ソースcrop/登録原点、解決倍率・原点・offset、丸め規約、placed bbox、見切れ、共有paletteとID、最終色数・alpha値、保護/削除/消失数を実測で記録する。未測定を0や合格にしない。
既存bboxレポートへ互換な追加を行うか、新版として分離する。旧キーの意味を置換しない。Study画像は利用者指定のGit管理外出力先へ保存する。新しい常駐データ・キャッシュ・アンインストール処理は不要。

## 9. エラー設計

「原点が未指定」→ガイド上で指定／設定項目を提示。「指定倍率では右側が見切れる」→不足pxと必要幅を表示。「原画の縮尺が不明」→基準長を指定。「保護領域が縮小で消失」→箇所を表示しサイズ変更を選べる。
空フレームの扱いは新モードで明示設定する。既定は拒否し、明示許可時はタイミングを維持して透明frameを出す。全frame透明はfit不能として拒否する。旧モードの挙動は変更しない。
エラー時は旧出力と原画を維持する。モデル内部用語だけを表示して行き止まりにしない。
