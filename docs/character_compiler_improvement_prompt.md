## 優先して直す範囲

### 1. キャラ向け経路をGUIから利用できるようにする

`gui/main_window.py` のCompilerConfig生成は現在、出力先・パレット数・繰り返し最適化だけを指定しています。既定のregion/repeatableが使われ、内部に存在するnearest/objectのキャラ向け経路をGUIから選べません。

「キャラクター」用途を選ぶと、最近傍変換、object、繰り返し最適化なし、ディザなしが一貫して適用されるようにしてください。既存の地形用途を残し、CLIとGUIで同じ設定なら同じ出力になることを確認してください。既に輪郭を持つ入力には追加輪郭を既定で付けないでください。

### 2. 可視画素だけからパレットを作る

`pixelizer/palette.py` のquantize_paletteは、透明部分を含むRGB全体でMEDIANCUTを行っています。最後に透明部分をゼロにしても、パレット選定への影響は消えません。

再現：64×64の透明画像の中央に16×16の可視領域を作り、4色を縦帯で配置。可視部分を固定し、透明部分のRGBだけをゼロと乱数に変えてbudget=4で比較すると、256/256の可視画素で出力色が変わりました。ゼロ背景でも4色のうち2色が混ざる結果になりました。

アルファの二値化基準を明示し、可視画素だけでパレットを選定・適用してください。完全透明入力、半透明境界、固定パレット指定にも対応してください。「色数予算」は可視RGB色数なのか透明色込みなのかを明確にし、メトリクスと表示を一致させてください。

### 3. 背景処理の順序と対象を改善する

`pipeline/compiler.py` のnearest経路は、add_edge_margin(loaded)の後にapply_backgroundを呼びます。autoは四隅のRGB平均を使うため、追加した透明黒の余白を背景色と誤認します。

再現：100×100の白背景に40×40の赤い矩形。背景処理単体なら可視1,600画素、余白追加後では可視10,000画素となり白背景が残りました。

元画像に対して背景を解決してから、人物のサイズ・余白を処理してください。既存アルファの透明領域をauto/color処理で不透明化しないようにしてください。背景色の許容差だけで画像内部を一括削除せず、外周につながる背景領域を対象にする方式を検討・実装してください。白背景と白い衣装のような入力を回帰例に含めてください。背景と輪郭が区別できない場合まで完全自動で解けるとは扱わないでください。

今回の生成画像には市松模様が実画素として描かれていました。ImageMagickの外周からのfloodfillで除去しましたが、許容差12%は今回の素材向けの値です。現行background_tolerance=12のRGB距離とは単位が異なるため、そのまま同値として移植しないでください。

### 4. 出力座標で人物の大きさと足元を揃える

`pixelizer/character.py` は入力全体を64×64に直接リサイズしています。add_edge_marginの2pxは入力側の単位なので、高解像度入力では縮小時に消えます。

再現：1024×1024の透明入力に上端へ接する矩形を置き、余白追加して64×64へ縮小すると可視bboxの上端は0でした。

キャラ用途では、可視bboxを取り出し、縦横比を維持して指定の描画枠へ縮小し、最終キャンバスへ配置する処理を設けてください。横長・縦長・完全透明入力を扱い、装備やリボンを切らないでください。出力側の余白、接地位置、水平中央を明示的に管理してください。

初期比較条件は64×64キャンバス、人物54×54以内、下余白7pxを候補にしてください。これは今回の54px高のアリアを既存コマンドで配置した場合に対応する候補で、全キャラ共通の確定設定ではありません。背の違いや武器を含む駒、将来の連番では個別bboxフィットによる大きさの揺れが起きるため、共通スケール・共通アンカーの拡張を妨げない設計にしてください。連番対応そのものは初回範囲外です。

## 目指す処理順

背景・アルファ解決 → 可視範囲抽出 → 縦横比を保つ最近傍縮小 → 可視画素のみで減色 → 必要な場合だけ輪郭 → 出力座標で配置 → PNGと検証情報を出力。

輪郭を付ける場合は、その幅と色も最終余白・色数予算に含めてください。生成で頭身や向きを整える工程と、決定論的に画像を変換する工程を混同しないでください。
