# 戦闘アニメーションの行別分割とAseprite向け連番出力

## 0. 実装担当への前提

本書は実装用の仕様書。保存時点では本書の機能変更を実装していない。
既存の[戦闘アニメーション仕様](battle_animation_compiler_spec.md)を補完する。
分割方式と最終フレーム名は本書を優先し、既存の共通変換・共有パレット・保護マスクの契約は維持する。

- `AGENTS.md`、作業差分、`fable-judgment`、`tdd-first`を確認する。
- G-1: 下記スコープ外の機能を追加しない。
- G-2: 受け入れ条件に対応する失敗テストを先に作り、最小実装後に責務分離を確認する。
- G-3/G-4: 新規依存・モデル・素材の導入はゼロ。既存画像処理を再利用する。
- G-5: スコープ・バジェット変更は本書に理由を記録してから実装する。
- 原画・既存成果物・他者の変更を保持する。実素材の比較出力は別フォルダへ保存する。
- 通常の実装判断は自律的に進める。隠れた絵の復元や曖昧なエフェクトの所属を推測で確定しない。
- コミット・プッシュ・既存成果物の一括リネームは今回の実装範囲外。

## 1. 概要と1動作デモ

戦闘ポーズの幅が異なるシートを、行ごとの透明な隙間で分割する。
切り出し範囲と配置原点を分離し、斬撃の欠け・隣コマの混入・切り出し変更による位置ずれを防ぐ。
最終PNGは単一の `final_frames` フォルダへ `F1.png`〜`Fn.png` として集約する。

デモ: GUIで対象原画、4列×2行、hybrid、128×128、24色を指定 → 検出線が斬撃を避けることを確認 → 変換 → `final_frames/F1.png`をAsepriteで開き連番として読み込む → 8フレームでF5/F6の斬撃とF7の混入が解消したことを確認。
Asepriteの連番取込操作・実際の順序は手動QAで確認し、命名だけで互換性検証済みとは扱わない。

## 2. ユーザー像と痛み

生成した戦闘アニメーションをAsepriteで編集したい利用者。
等分割で攻撃エフェクトが欠け、隣のコマに混じるため手直しが必要になっている。
利用者指定により、最終連番のファイル名に `_final` を付けない。
価格・販売形態の変更は本機能に関係しない。

## 3. スコープ

| 区分 | 内容・難易度 | 理由 |
|---|---|---|
| やる | 行別の透明帯分割とhybridへの組込（M） | 今回の画像を切断なしで抽出する |
| やる | 切り出しと論理原点の分離、共通倍率維持（M） | 可変幅抽出によるアニメーションのずれを防ぐ |
| やる | 切断診断・レポート・GUI/CLI表示（M） | 誤った等分割を正常として報告しない |
| やる | `final_frames/Fn.png`への変更と保存互換性検証（S） | Aseprite向けの利用者要件 |
| やらない | 成分の所属推定・AIセグメンテーション | 離れた火花や接触したコマは別問題 |
| やらない | 手動境界エディタ・骨格/足位置の自動推定 | 今回の分割改善には不要 |
| やらない | 隠れた画素の生成、パレット・細部処理の再設計 | 元画像保持と責務を守る |
| やらない | MAPタイル分割の変更・新規基盤構築 | キャラクターアニメーション経路に限定 |
| いつか | 離れたエフェクトのグループ化、手動所属指定 | 透明帯で分けられない実例を集めて別仕様化 |

## 5. アーキテクチャと動作契約

### 5.1 責務と変更候補

- `sheet/alpha_projection.py`: 既存モード、マスク、セル情報、診断を再利用。
- 必要なら `sheet/row_projection.py`へ行別帯検出・境界選択を切り出す。配置・保存は持たせない。
- `pixelizer/character_animation.py`: 抽出座標から共通座標への変換、既存配置への接続、最終PNG集約、レポート。
- `cli.py` / `gui/main_window.py`: モード追加、診断表示、既存原点指定への接続。独自の分割ロジックを持たせない。

### 5.2 モードと選択順

- 明示モード `row_alpha_gap` を追加。GUI名は「行ごとの透明部分で分割」。
- `fixed_grid`は明示的な等分割として維持。切断診断は追加する。
- 既存`alpha_gap_auto`の検出契約は維持する。
- `hybrid`は既存自動検出 → 行別分割 → fixed_gridの順に試す。
- 行別分割は設定済みrows/columnsを期待値として使う。各行のコマ数がcolumns、行数がrows、総数がframe_countと一致すること。
- hybridの既存自動検出も期待数を確認し、不一致なら次候補へ進む。勝手なコマ数変更は禁止。
- 行別分割を明示して検出に失敗した場合はエラー。hybridの最後のfixed_gridは互換のため出力可能だが、失敗理由と切断警告を表示する。

### 5.3 行別分割アルゴリズム

1. 既存のalpha_threshold、微小成分除去、保護マスクの扱いと整合する検出用マスクを作る。検出の都合で原画RGBAを書き換えない。
2. Y投影から可視帯を検出し、短い隙間を既存min_gutter_width_pxで結合する。行数が期待値と一致しなければ不採用。
3. 各行の範囲でX投影を計算し、同様に帯を検出する。各行で期待列数に一致しなければ不採用。
4. 隣り合う可視帯の終端eと次の開始sの間で、境界を `floor((e+s)/2)` に置く。外周は元画像の0/width/height。入力の端数をcenter_cropしない。
5. empty_thresholdが許す低密度画素が境界に残る場合、同じ隙間候補の中でマスクが境界をまたがない位置を探す。中央から距離が近い順、同距離は小さい座標を優先。安全な境界がなければ不採用。
6. 隣接帯間に安全な境界がある限り、可視幅・高さの比率で不採用にしない。max_cell_size_variance_ratioは既存方式専用とする。
7. 上から下、各行の左から右へF1〜Fnを割り当てる。source_boxは可変幅の整数矩形、content_boxはその内部の検出した可視範囲とする。
8. 各source_boxは互いに重複せず元画像全域を分担する。抽出段階で画素の欠落・重複を作らない。保護対象を横切る境界は認めない。

今回のマスクならY境界471、上段X境界457/859/1293、下段527/972/1354を得る。これは計算結果の期待値でありパラメータに固定しない。

### 5.4 抽出範囲と配置原点

可変幅の切り出し画像をそのまま左上揃えして既存union計算へ渡すだけでは不十分。
行別分割でも、分割位置に依存しない論理フレーム座標を保持する。

- 論理セルの左上L_iは元画像をrows/columnsで等分した従来の位置規約から決定し、メタデータに明示する。端数処理の規約を固定してテストする。
- 行別モードの新規入力では `L_i=(round(column*W/columns), round(row*H/rows))` とする。これは配置の基準であり、切断線ではない。
- 元画像座標pの論理座標は `q=p-L_i`。切り出し左上C_i、切り出し内座標uなら `q=u+C_i-L_i`。
- マイナス座標・論理セル外への張り出しを許す。全フレームを収納する共通作業キャンバスの平行移動を一度求め、原点にも同じ移動を適用する。
- preserve_motionでは既存の共通原点O、倍率s、出力原点Aを使い、`out=A+s*(q-O)+既存規約のframe_offset`。offsetの単位・順番は既存契約を維持し、二重適用しない。
- GUIクリックの原点・保護マスクもC_i/L_iを介して変換する。抽出画像のローカル座標を論理座標と取り違えない。
- legacy_footは既存の足元固定を維持する。Xの登録は上記論理座標を使い、各フレームの可視bbox中心へ独立に中央寄せしない。
- 全フレームを共通倍率で縮小。今回の完全な斬撃が収まることで、従来の欠けた成果物と共通倍率が変わることは許容する。
- 既存fixed_grid/alpha_gap_autoの配置結果は変更しない。row_alpha_gapに必要な登録情報は明示して受け渡す。
- 本方式は元絵の配置誤差を補正する機能ではない。不規則に並べた絵の本体原点は自動推定しない。

### 5.5 診断と保存スキーマ

- `cells[].source_box`を抽出範囲の正本とする。行ごとに異なるX境界を共通x_bandsへ偽装しない。
- 行別結果には`row_bands`（row、y範囲、x範囲一覧）、各セルの`logical_origin`、登録用の平行移動を保存する。
- 既存のグローバルx_bandsは行別モードでは空配列とし、新しい読取側はcells/row_bandsを参照する。既存モードの形式は保持する。
- `detected_mode="row_alpha_gap"`、試したモードと失敗理由、期待数/実検出数を記録する。新スキーマは現行2から3へ更新し、既存レポート読取箇所を確認する。
- `boundary_crossings`に方向・座標・該当行/フレーム・境界に接する可視画素数を記録する。8近傍で境界をまたぐ連結を切断とする。
- `quality_status`は`passed`/`warning`。切断があればwarning。切断ゼロは意味的な所属の正しさを保証しない旨を仕様上区別する。
- confidenceを残す場合、検出確率とは呼ばない。安全な検出は既存計算または1.0、fallbackや切断があれば0.0として定義し、quality_statusと併記する。
- fallback/切断を`issues`および最上位`warnings`へ伝播する。出力配置の`clipped`は別指標として維持。
- overlayは実際に使用したsource_boxを描画する。危険な境界は安全な境界と色を変えて表示。

## 8. データとファイル配置

```text
<output_root>/
  final_frames/
    F1.png
    F2.png
    ...
    F8.png
  compiled/F1/final.png
  compiled/F2/final.png
  ...
  aligned_sheet.png
  compiled_sheet.png
  compiled_sheet_8x.png
  detection_overlay.png
  bbox_report.json
```

- 変更対象は利用者がまとめて取り込む`final_frames`内の名前。大文字F、1開始、ゼロ埋めなし、拡張子小文字png。
- `Fn_final.png`は生成しない。別名コピーも置かない。`final_frames`というディレクトリ名、内部`compiled/Fn/final.png`は維持する。
- `final_frame_paths`とJSONの`final_frames[].path`を新しい実ファイルへ更新。frame_idは従来通りFn。
- 配列とシートの順序は整数インデックス順。文字列ソートでF10をF2より前にしない。
- 既存のトランザクション出力置換を維持し、同一出力先への成功時再実行で管理対象final_framesを更新する。失敗時は以前の出力を維持する。
- 既存成果物は起動時に走査・リネームしない。再変換した成果物から新命名を適用する。
- アプリ設定の保存先・アンインストール挙動は変更なし。

## 9. エラー表示

明示行別モードの失敗例:
「2行目を4コマに分割できませんでした（検出5コマ）。離れたエフェクトや透明な隙間を確認してください。」

hybridで危険な等分割に戻った例:
「自動分割できなかったため等分割しました。F5とF6の境界が絵を横切っています。分割プレビューを確認してください。」

開発者向け詳細は試行方式、設定値、行番号、境界座標をJSONへ保存する。
GUIで単に「完了」だけを表示しない。CLIは互換上出力成功なら既存成功終了コードを維持しつつ警告を出す。
