`E:\ena-dri\repos\pixelart-compiler` で、ピクセルアート風のMAPタイル入力を、地形構造と隣接関係を守った64×64pxのピクセルアートへコンパイルする経路を実装してください。

## 初回の実装範囲

### 1. 接続を守るコンパイル

`tile/repeatability.py` は画像自身の対向辺を揃えます。道・川・境界・Wang型タイル・MAP固定配置にも `repeatable` が使われる現行の呼び出しを追跡し、適用条件を整理してください。

最初の再現例は64×64画像の上半分 `(30,140,40,255)`、下半分 `(150,90,40,255)`。`optimize_repeatability(image, center_suppression_strength=0)` では192画素が変わり、北端と南端が同じになりました。関数の自己反復用途としては成立するため、関数全体を無効化するのではなく、地形用途での誤適用を修正してください。

自己反復、隣接契約付き、MAP固定配置を区別し、既存単体反復を維持してください。新しい型・保存形式が必要なら、既存設定に閉じる案と明示的な契約を追加する案を比較し、最小の互換性ある方式を選んで理由を記録してください。

草・土・草土境界・道の小セットを対象に、最終64pxの接続位置・幅・非接続辺を保護してください。減色やクラスタ整理による破損も確認すること。単に `repeat_opt_enabled=False` にして全解決と扱わないでください。

### 2. シート入力からコンパイルまで接続

`asset/pipeline.py::process_generated_sheet()` は現在、分割・縮小した画像を直接保存します。`sheet/normalizer.py` の `pixel_preserving` は最近傍縮小であり、減色ではありません。

元シートの高解像度セルを取り出し、既存 `PixelTileCompiler` を再利用して64pxへ変換し、最終PNGをパッケージ化する明示的な経路を追加してください。先に64pxへ縮小して解析情報を失う順序にしないこと。

初期のタイル一式は共通パレット・共通設定で処理できるようにしてください。地形にキャラクター用bboxフィット・足元余白・追加輪郭を適用しないでください。既存の分割のみの経路は残し、利用者の指定なしに既存出力を再解釈しないこと。

入力セルの行列順・切り出し領域・IDを追跡可能にしてください。余白やガターのあるシートを誤って受理しないよう、明示的な指定または対応外の通知を設けてください。生成画像のセルずれを万能に自動修復することは求めません。

CLIまたは既存の公開エントリーポイントから再現できるようにし、画像処理をGUIへ埋め込まないでください。

### 3. 最終PNGに対する採用ゲート

接続IDの一致、入力マスクの連続性、完成PNGの整合性を分けて検証してください。

- 最終PNGの接続位置・幅、非接続辺への漏れ、隣接境界と四隅を確認する。
- 許可する組み合わせの検証範囲を宣言し、未比較を合格にしない。
- 画素単位一致が必要な契約と、見た目の連続性を評価する指標を区別する。無関係な全辺を同色に揃えない。
- 色で意味を推定する場合の限界を記録する。マスクだけ正しく、PNGが壊れた例も検出する。
- 局所破損を平均点で隠さず、必須契約違反を拒否する。
- 色数、アルファ、64×64寸法、ID・座標の重複欠落も確認する。
- 暫定出力は検査用に保存できても、拒否されたものを採用済み扱いしない。自動の美観スコアだけでapprovedへ変更しない。

しきい値を根拠なく固定しないでください。構造の厳密条件と、調整可能な見た目の指標を分けてください。

### 4. 検証と比較成果物

回帰テストを先に作り、上記の不具合が失敗として観測できることを確認してから修正してください。

最低限の例:

- 北が草・南が土、および逆方向の境界。
- 道の直線、曲線、端点、T字。接続がない辺へ道を出さない。
- 草・土の自己反復、契約付き隣接、MAP固定配置の違い。
- 入力マスクは正しいが完成画像の接続画素を壊した負例。
- シート分割のみとコンパイル経路の区別、共有パレット、行列とIDの保持。
- キャラクター64×64・128×128と既存単体反復の回帰。

合成画像は構造の厳密検証に使い、画風の改善を証明したとは報告しないでください。実在する素材を確認して、同一入力・同一色数条件の変更前後比較を出してください。実画像が不足する場合は、その不足を記録し、独立して進められる実装を完了してください。

成果物は既存出力と衝突しない別ディレクトリへ保存してください。固定MAP、各タイル、実寸、最近傍整数拡大、検証結果、再実行コマンド、入力ハッシュと設定を残してください。存在する採用済みキャラクターを参照できる場合はMAPへ重ねた確認画像も作り、参照元を記録してください。

## 初回の受け入れ条件

1. シートの高解像度セル→共有条件での64pxコンパイル→検証付きパッケージが再実行可能。
2. 境界の北・南を無条件に同一化せず、宣言した接続位置・幅・非接続辺を完成PNGで維持する。
3. 接続違反の負例がゲートで拒否され、未検証が合格にならない。
4. 全タイル64×64、指定した色数・アルファ条件、IDと座標の完全性を満たす。
5. 同一入力・設定・seedで同一画素を出力し、原画と既存成果物を変更しない。
6. 関連テストとキャラクター・単体地形の回帰が確認されている。
7. 実画像の比較結果と、人の目による採用確認が必要な箇所が区別されている。
